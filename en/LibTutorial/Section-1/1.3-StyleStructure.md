<h1 align="center">Style structure</h1>

<hr>

- This library assumes that you have already studied [basic guide tModLoader user-interface](https://github.com/tModLoader/tModLoader/wiki/Basic-UI-Element)<br>
- This library assumes that you have already studied [Extended Guide to Configuring the User Interface](https://github.com/tModLoader/tModLoader/wiki/Advanced-guide-to-custom-UI)<br>

<hr>

Styles in this library are divided into 4 types:
1. Visual display styles.
2. Visual styles of elements from **tModLoader**
3. Container layout styles.
4. Styles of the layout of a separate element.

----

- **Visual display styles** These are all styles that are responsible for the entire visual part, except for the location of the element (color, shape, trimming, etc.).

----

- **Visual styles of elements from tModLoader** Styles that allow you to set the style parameters of the basic elements **tModLoader**.<br><br>

Clarification is required in this paragraph.<br>
Any element in a given library may adopt the visual style of a given library (see previous paragraph) or the style of an element. **tModLoader**.<br>
For example, an element `UIExElement` can adopt a visual style `UIPanel`.<br>
Details below.

----

- **Container layout styles** These are all styles that are used only by component builders (*)UIExStackPanel*, *UIExDockPanel*, *UIExGridThey contain general rules about how to arrange elements within oneself.

----

- **Styles of individual element layout** These are all the styles that an element builder uses in relation to an individual *UIElementThis will be discussed in more detail in the section on the layout of the elements.

----

This article will not deal with individual style classes. `UIExElement` (`UIExLayout` for layout styles) and will be discussed in conjunction with these elements in the following sections.

<h2 align="center"><b>Visual display styles</b></h2>

**Important!** The library is under development.<br>
In this block of **visualization styles** Information to understand the overall style system.<br>
At the moment, the library has only containers of layouts (about them below). `UIExElement`.<br><br>

`UIExElement` It keeps a field in it:
```csharp
public class UIExElement : UIElement
{
  public Styles.StyleVisualElement StyleDisplay;
}
```
Accordingly, this field is inherited by all elements of the library.<br>
Visual styles for **anyone** Elements will be set through this field.


Class `StyleVisualElement` Keeps the styles of everyone `UIExElement` and methods that return the styles of any class of heirs `UIExElement`.<br>
For example, there are classes (given as an example; in development):
```csharp
public class UIExButton : UIExElement {}
public class UIExTextBlock : UIExButton {}
```
<br>

In this case, the library will have appropriate style classes:
```csharp
public class StyleVisualButton {}
public class StyleVisualTextBlock {}
```
<br>

Class. `StyleVisualElement` will have the following methods:
```csharp
public class StyleVisualElement
{
    public StyleVisualButton Button() { /* ... */ }
    public StyleVisualTextBlock TextBlock() { /* ... */ }
}
```
<br>

Now we can get styles as follows:
```csharp
UIExElement element = new();
UIExButton button = new();
UIExTextBlock textBlock = new();

StyleVisualElement elementStyleDisplay = element.StyleDisplay;
StyleVisualElement buttonStyleDisplay = button.StyleDisplay;
StyleVisualElement textBlockStyleDisplay = textBlock.StyleDisplay;

StyleVisualButton buttonStyle = buttonStyleDisplay.Button();

StyleVisualTextBlock textBlockStyle = textBlockStyleDisplay.TextBlock();
```
<br>

<h2 align="center"><b>Visual styles of elements from tModLoader</b></h2>

Instead of using **visualization** In a given library, you can specify to an item that it must use the style of a particular (the item decides which) element. **tModLoader**.<br>
For that, in the field. `StyleDisplay` need to specify `tModLoaderStyle = true`.
```csharp
UIExElement element = new();
element.StyleDisplay.tModLoaderStyle = true;
```

Each element decides the style of which element. **tModLoader** to use him.<br>
`UIExElement` And any element of the layout in this case will use the style. `UIPanel`.<br>
- It's a library that's under development. There's no other elements to date.<br><br>

You can get a basic style class and change its meanings.<br>
```csharp
UIExElement element = new();

element.StyleDisplay.tModLoaderStyle = true;

StyleTmlUIPanel styleTmlUIPanel =  element.StyleDisplay.TmlUIPanel();
styleTmlUIPanel.BackgroundColor = Color.Red;
```

In this example, the `UIExElement` It will look like `UIPanel`But it will be the color red.<br>

Class names of style and method:
- The name class begins with `StyleTml`and then: the name of the element **tModLoader** appropriate style.
- The name of the method begins with `Tml`and then: the name of the element **tModLoader** appropriate style.

Storage and obtaining container layout styles are identical **visualization**<br>

```csharp
class UIExLayout : UIExElement
```

<br>

Class `StyleLayoutContainer` analogously `StyleVisualElement` It retains methods that bring back the styles of heir class container layout:

```csharp
UIExLayout layout = new();
```

<h2 align="center">Styles of individual element layout</h2>

The system is very similar here, but unlike the previous examples, the layout style of an individual element can have any type of structure. `UIElement` into **tModLoader**.<br>
Therefore, obtaining these styles occurs using the method of expansion. `UIElement.StyleLayoutChild()`
```csharp
UIElement element = new();
StyleLayoutChild styleLayout = element.StyleLayoutChild();
StyleLayoutChildCanvas styleLayoutCanvas = styleLayout.Canvas();
```
<br>

The regularity between the name of container layout styles and individual elements:
- `UIExLayout` - `StyleLayoutContainer` - `StyleLayoutChild`
- `UIExCanvas` - `StyleLayoutContainerCanvas` - `StyleLayoutChildCanvas`
- `UIExStackPanel` - `StyleLayoutContainerStackPanel` - `StyleLayoutChildStackPanel`<br>

As you can see, class names begin with `StyleLayout` - It goes on. `Container/Child` the name of the container (except for the `UIExLayout`).

<h2 align="center">Additional information</h2>

All style classes are heirs to the class. `StyleBase`.<br>
This class has only 1 public method.
```csharp
public bool EqualsStylesFields(StyleBase other) { /* ... */ }
```
This method checks whether all fields of all transferred styles are the same.<br>
For example:
```csharp
StyleLayoutChildCanvas styleCanvas = new();
StyleLayoutContainer style1 = new();
StyleLayoutContainer style2 = new();


//////////////////

// [1]: the method will return false
style1.EqualsStylesFields(styleCanvas);


//////////////////

// [2]: the method will return true
style1.EqualsStylesFields(style2);


//////////////////

style1.JustifyContent = UIExAlignment.Center;

// [3]: the method will return false
style1.EqualsStylesFields(style2);


//////////////////

style2.JustifyContent = UIExAlignment.Center;

// [4]: the method will return true
style1.EqualsStylesFields(style2);


//////////////////

style1.UniformGrid();

// [5]: the method will return false
style1.EqualsStylesFields(style2);


//////////////////

style2.UniformGrid();

// [6]: the method will return true
style1.EqualsStylesFields(style2);


//////////////////

style2.UniformGrid().ColumnsCount = 5;

// [7]: the method will return false
style1.EqualsStylesFields(style2);
```

Challenge results `EqualsStylesFields`:
1. It compares two different style classes. `false`.
2. Compare the two styles to the default fields. `true`.
3. Woo `style1` significance `JustifyContent` It's changed. `style2` The fields of style are different. `false`.
4. Woo `style2` significance `JustifyContent` changed to identical `style1`The fields of style are the same. `true`.
5. For `style1` registered `StyleLayoutContainerUniformGrid`For me. `style2` - unregistered. `false`.
6. For `style2` registered `StyleLayoutContainerUniformGrid`For me. `style1` This style has been registered before. `true`.
7. Value of the field `ColumnsCount` registered-style `StyleLayoutContainerUniformGrid` `style2` It's different. It's different. It's different. It's different. `false`.

----

All style classes contain 2 constructors:
1. By default.
2. Accepting all values for the fields of a given style class (not specified take the default value).

----

All style classes contain public techniques according to the template below:
```csharp
/*

public void Set(
	type FIELD_1 = default(type), 
	type FIELD_2 = default(type), 
	..., 
	type FIELD_N = default(type))
		=> SetAllFields(
			FIELD_1, 
			FIELD_2, 
			..., 
			FIELD_N);



public void Copy(TYPE_STYLE style)
    => SetAllFields(
			style.FIELD_1, 
			style.FIELD_2, 
			..., 
			style.FIELD_N);

public TYPE_STYLE GetCopy()
    => GetCopyBase<TYPE_STYLE>();

*/
```

1. Method `Set` accepts all the values of the fields that this style contains (not specified take the default values).
2. Method `Copy` adopts a similar style and copies all fields of the transferred style.
3. Method `GetCopy` returns a new style object with a copy of all the fields of the class (including a copy of the registered styles).

----

1. **Visual display styles** Inherit the class: `StyleVisualElementBase`.
2. **Visual styles of elements from tModLoader** Inherit the class: `StyleTmlBase`.
3. **Container layout styles** Inherit the class: `StyleLayoutContainerBase`.
4. **Styles of layout of nested elements** Inherit the class: `StyleLayoutChildBase`.<br>
