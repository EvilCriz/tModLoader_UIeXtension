<h2 align="center">Reducing the number of layouts</h1>

**tModLoader** It recalculates the sizes of each tick for the open interface. `UIElement` Your interface will be called the method. `Recalculate`.
<br>

Imagine that we have a user interface with *1000* elements, *400* of which are layout elements, which means that each frame for all *1000* elements will be called. `Recalculate`And after the recalculation, the layout of the elements will also change, which means that in addition to the *1000* recalculations of the dimensions, we will also have *400* algorithms for the layout of the elements, which, as you can see, will make this interface (and therefore this library) unviable.
<br><br>

This library solves this problem as follows:<br>
Each container of the layout remembers:
- Your size on the last call. `Recalculate`.
- List of items at the last call `Recalculate`.
- Element sizes at the last call `Recalculate`.
- Container layout styles.
- Styles of layout of nested elements.

If:
1. The size of the container has not changed.
2. The elements inside the container have not changed.
3. The size of the components inside the container has not changed.
4. Container/element styles have not changed.<br>

The layout is not running.
<br>

The information above might not have been written, because it's all done by the builder, but then there's the next problem.
Let's imagine the following code.

```csharp
UIExStackPanel stackPanel = new();
UIPanel panel1 = new();

// for panel1 and all its descendants (which are not in this example) called the method `Recalculate`.
// but stackPanel He doesn’t know that a new element has been added.
// tModLoader It is not possible to learn about the event of adding an element to another.
stackPanel.Append(panel1); 


// at this point is called `Recalculate()` and `RecalculateLayout()`The elements and the dimensions are checked. The entire layout cycle is performed.
Append(stackPanel);


// into stackPanel There's a new element added. stackPanel He doesn't know that.
// However, it already stores a list of items after the previous layout.
// next-tick stackPanel provoked `Recalculate`.
// The container determines that the item has changed. The entire layout cycle is executed.
UIPanel panel2 = new();
stackPanel.Append(panel2); 
```

<br>

As seen in the code above: `stackPanel` I counted the layout twice, although in fact he had to do it only 1 time.
There are two solutions to this problem:

<br>

1. Ensure that elements are always added to the linker **DOO** How the linker itself will be added to the parent element.
2. Use methods `BeginLayoutPreparation` and `EndLayoutPreparation`which we will discuss in detail below.

----

```csharp
public static void BeginLayoutPreparation(UIState state)
	=> _statesPreparationTable.TryAdd(state, _preparationStateMarker);

public static void EndLayoutPreparation(UIState state)
{
    ResetСurrentRecalculateLayoutDelayMsBranch(state);
    ResetLastLayoutInfoForBranch(state);

    if (_statesPreparationTable.TryGetValue(state, out _))
        _statesPreparationTable.Remove(state);

    state.Recalculate();
}
```

- Method `BeginLayoutPreparation(UIState state)` pass-in `UIState` table `_statesPreparationTable`.
- Since the call of this method `RecalculateLayout` It will not be implemented (nowhere in the world). `UIState`) before being called `EndLayoutPreparation`
<br>

- Method `EndLayoutPreparation(UIState state)` drop off `UIState` table `_statesPreparationTable`.
- From now on, the action `BeginLayoutPreparation` It stops and the layout works again. `UIState`.
- `ResetLastLayoutInfoForBranch` makes all descendants `UIState` ignore **single** The following layout, information about which was mentioned earlier:
  - Your size on the last call. `Recalculate`.
  - List of items at the last call `Recalculate`.
  - Element sizes at the last call `Recalculate`.
  - Container layout style on the last call `Recalculate`.
  - Styles of layout of nested elements at the last call `Recalculate`.
- `ResetСurrentRecalculateLayoutDelayMsBranch` cast off for all descendants `UIState` field `СurrentRecalculateLayoutDelayMs`, which will be discussed below.
<br><br>

We will rewrite the previous code with new information:
```csharp
UIExLayout.BeginLayoutPreparation(this);

UIExStackPanel stackPanel = new();
UIPanel panel1 = new();

// for panel1 and all its descendants (which are not in this example) called the method `Recalculate`.
// but stackPanel He doesn’t know that a new element has been added.
// tModLoader It is not possible to learn about the event of adding an element to another.
stackPanel.Append(panel1);


// at this point is called `Recalculate()` and `RecalculateLayout()`.
// `ExamplePanelUI` tabular `_statesPreparationTable`.
// Verification of elements and dimensions is not carried out.
// The composition of the elements does not occur.
Append(stackPanel);


// into stackPanel There's a new element added. stackPanel He doesn't know that.
// It does not store a list of items after the previous layout.
// Because there was no layout before that.
UIPanel panel2 = new();
stackPanel.Append(panel2);


// `ExamplePanelUI` drop-off `_statesPreparationTable`.
// All other limitations of the layout are ignored in this recomposition.
// for daughters `ExamplePanelUI`.
// Recalculation of sizes and recomposition of all descendants `ExamplePanelUI`.
UIExLayout.EndLayoutPreparation(this); 
```

----

But even in this case, all checks for changes in the layout will be carried out every frame.<br>
The ideal solution will be after the call. `UIExLayout.EndLayoutPreparation(this);` call back `UIExLayout.BeginLayoutPreparation(this);`.<br>
In this case, the linker will not even try to check the changes to the information itself.<br>
In this case, the responsibility for calling the life cycle of the layout lies with the end user.<br>
This means that the end user independently monitors when the linker needs to recompose the elements.<br>
Then the method is called again: `UIExLayout.EndLayoutPreparation(this);`and then again `UIExLayout.BeginLayoutPreparation(this);`

----

Another problem is the stretching of the container or its daughters, in which case the dimensions will change all the time, and as a result, each frame will be rearranged.<br><br>
There are two solutions to this problem:<br>
1. Use tools. `BeginLayoutPreparation` and `EndLayoutPreparation` Now, if you know that you're going to resize a lot right now, you can temporarily disable the layout.
2. Use it. `RecalculateLayoutDelayMs`, `SetRecalculateLayoutDelayMsBranch` or `SetRecalculateLayoutDelayMsState`:<br>
```csharp
public class RecalculateLayoutStateDelay
{
    public int? DelayMs = 0;
}

public abstract partial class UIExLayout : UIExElement
{
    private static readonly System.Runtime.CompilerServices.
        ConditionalWeakTable<UIState, RecalculateLayoutStateDelay> _statesRecalculateDalayMs = new();

    public int RecalculateLayoutDelayMs = 0;

    public static void SetRecalculateLayoutDelayMsBranch(UIElement element, int ms)
    {
        if (element is UIExLayout layout)
            layout.RecalculateLayoutDelayMs = ms;

        foreach (var child in element.Children)
            SetRecalculateLayoutDelayMsBranch(child, ms);
    }


    public static void SetRecalculateLayoutDelayMsState(UIState state, int? delayMs)
    {
        if (_statesRecalculateDalayMs.TryGetValue(state, out RecalculateLayoutStateDelay delay))
            delay.DelayMs = delayMs;
        else
        {
            RecalculateLayoutStateDelay delayNew = new() { DelayMs = delayMs };
            _statesRecalculateDalayMs.Add(state, delayNew);
        }
    }

    public static int? GetRecalculateLayoutDelayMsState(UIState state)
    {
        if (_statesRecalculateDalayMs.TryGetValue(state, out RecalculateLayoutStateDelay delay))
            return delay.DelayMs;

        return null;
    }
}
```

These settings are determined in the class `UIExLayout`They're responsible for the minimum delay in milliseconds in the layout of a particular element.<br>
That is, after the linker has recalculated the layout, it sets the delay before the next layout in the amount of `N` ms.<br>
- If `GetRecalculateLayoutDelayMsState(firstParentState) is not null` Delay will be determined by this method.
- If `GetRecalculateLayoutDelayMsState(firstParentState) is null` - the delay will determine `RecalculateLayoutDelayMs`.
- Method `SetRecalculateLayoutDelayMsState(UIState state, int? delayMs)` It allows you to determine the delay of a certain `UIState`If in `delayMs` delivered `null` - Removes delay for the transferred `UIState`.
- Method `SetRecalculateLayoutDelayMsBranch` allows you to set the delay `RecalculateLayoutDelayMs` the elements passed on and to all descendants.
