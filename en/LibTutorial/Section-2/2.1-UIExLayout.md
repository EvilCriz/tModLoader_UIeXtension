<h2 align="center">Styles of container layout and nested elements</h2>

Class `UIExLayout` defines the field:

```csharp
public Styles.StyleLayoutContainer StyleLayout;
```

This field contains layout styles that any container layout implements.<br>

Type of data `Styles.StyleLayoutContainer` has the following implementation:
```csharp
public class StyleLayoutContainer() : Base.StyleLayoutContainerBase
{
    public UIExOrientation Orientation = UIExOrientation.Vertical;
    public UIExAlignment JustifyContent = UIExAlignment.Auto;
    public UIExAlignment AlignItems = UIExAlignment.Auto;
}
```

- `Orientation` determines which axis will be considered the main for the container and which is the transverse axis.
- `JustifyContent` and `AlignItems` indicates how the elements will be aligned along the main and transverse axes. `UIExAlignment` may take the following meanings:
  - `Start`: alignment at the beginning of the main / transverse axis.
  - `Center`: centre alignment of the main/transverse axis.
  - `End`: alignment at the end of the main/transverse axis.
  - `Stretch`: stretches along the main/transverse axis.
  - `Auto`: this value is used only by the elements nested in the container (see below). `JustifyContent` and `AlignItems` equalize `Start`.

----

Class `Styles.StyleLayoutChild` defines the layout styles for the container’s child elements.

```csharp
public class StyleLayoutChild : Base.StyleLayoutChildBase
{
    public UIExAlignment JustifySelf = UIExAlignment.Auto;
    public UIExAlignment AlignSelf = UIExAlignment.Auto;
	
	public UIExThickness Margin = new();

	public bool WithoutLayout = false;

	public StyleDimension Width = default(StyleDimension);
	public StyleDimension Height = default(StyleDimension);
}
```

`JustifySelf` and `AlignSelf` determines how the element will align along the main / transverse axis. `UIExAlignment`Except for the meaning. `Auto`And for the container's child elements, that value is key.<br>

If the container has a value `JustifyContent == UIExAlignment.Center` - this means that all the elements inside the container will be centered (the center of which depends on the linker) along the main axis. `JustifySelf == UIExAlignment.Auto`.<br>

`Auto` for the nested element, it means that it will take the value of the container. `JustifySelf` redefine `JustifyContent` for this particular element.<br>

For `AlignSelf` The situation is similar for the transverse axis.<br>

Pro `Margin`, `Width`, `Height` We'll talk in more detail below.<br>

<h2 align="center">Position and size of nested elements</h2>

About the positions you need to know the following:
- Components never look at values. `Left`, `Top` class `UIElement`.
- Components set these values, ignoring their values set before the layout.<br>
<!-- -->
- Only one linker allows you to set the absolute coordinates of the element: `UIExCanvas`.
- `UIExCanvas` permitting **4** absolute coordinates using a special class of styles of nested elements.
- All other builders use completely different systems.<br>
<!-- -->
To summarize:
- Meanings `Left` and `Top` elements embedded in the layout do not affect the layout, and after the layout, most likely, will differ from their values before it.<br>

----

About the size you need to know the following:
- Components never look at values. `Width`, `Height` class `UIElement`.
- Components set these values, ignoring their values set before the layout.<br>
<!-- -->
- Initial sizes are determined by `Width` and `Height` class `StyleLayoutChild`.
- These sizing values from the style class are only used by linkers. Outside the linkers, they don't do anything.
- `MinWidth`, `MaxWidth`, `MinHeight` and `MaxHeight` They're used as normal. The class doesn't have any field data. `StyleLayoutChild`, and their meanings are taken from `UIElement`.<br>
<!-- -->
Why would a builder need separate identical fields?
- Part of the linkers simultaneously changes the dimensions and assembles based on the original dimensions of the elements.
- Thus, the linker can change the size, set the fields. `Width` and `Height` specific `UIElement` And the next time you put it together, the original dimensions will be lost.
- Thus, the layout will give completely different results with each iteration.
- To eliminate this problem, separate size fields were introduced.

<h2 align="center"><code>Margin</code>, <code>Padding</code>, <code>Stretch</code> 3 areas of the element</h2>

This section provides a detailed description of the library layout model.
This information is especially important in 3 cases:
1. You plan to draw your own elements on the screen (then just do it yourself). `Left`, `Top`, `Width`, `Height` It won't work.
2. You are planning to write your own compositor based on this library.
3. You would like to understand how the general principle of the linker disposes the elements (considering `Margin`, `Padding`, `Stretch`, its area and areas of elements).

Each element has 3 regions (top-left angle coordinates + size):
1. The area of the element itself.
2. The outer region of the element.
3. The inner region of the element.<br>

Any containers in the layout work **purely** with the outer region of the element.<br>
This is the main thing you need to know when working with the builder of this library or creating your own.<br>
The container does not care about the normal or internal area of the element.<br>
The container is only important:
1. My own inner region.
2. The outer region of the child elements.

**Area of the element itself** - It's not easy. `Left`, `Top`, `Width`, `Height`.<br>
`Left` and `Top` It is a displacement of the element relative to the inner region of the parent element. 
After the recalculation `UIElement` stores the area of the element as follows:
1. `X-области`: `X` internal area of the parent (in absolute coordinate from the beginning of the screen) `Left-элемента`.
2. `Y-области`: `Y` internal area of the parent (in absolute coordinate from the beginning of the screen) `Top-элемента`.
3. `ActualWidth-области`: `Clamp(Width, MinWidth, MaxWidth)`.
4. `ActualHeight-области`: `Clamp(Height, MinHeight, MaxHeight)`.<br>

The area of an element is its absolute coordinates. **X/Y** from the beginning of the screen + element size, limited `Min` and `Max`.

----

**Area of the element itself (paragraph 1)** It is determined (for the builders of this library) by the following algorithm:
1. The size of the free space area (dedicated by the linker) for placement is taken.
2. Based on the size of the area of allocated space and values (`Width`, `MinWidth`, `MaxWidth`, `Height`, `MinHeight`, `MaxHeight`) the size of the element is determined.
3. Based on the displacement of the area of allocated space and values `Top` and `Left` The current position of the item is determined (relative to the start of the screen, not the parent element).
For example:
```csharp
// method OnActivate(a) in this case, only
// for the “hot code reboot” function in the development environment.
// It would be better to use the real interface.
// method OnInitialize()
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Left.Precent = 0.1f;
    canvas.Top.Precent = 0.1f;
    canvas.Width.Precent = 0.8f;
    canvas.Height.Precent = 0.8f;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();
    StyleLayoutChildCanvas innerPanelStyleCanvas = innerPanelStyle.Canvas();

    innerPanel.MaxWidth.Set(50f, 0f);
    innerPanelStyle.Width.Pixels = 100f;
    innerPanelStyle.Height.Precent = 0.5f;

    innerPanelStyleCanvas.Left.Pixels = 50f;
    innerPanelStyleCanvas.Top.Pixels = 50f;

    canvas.Append(innerPanel);
    Append(canvas);
}
```
1. `canvas` It starts at 10 percent of the height/width of the screen, and it's 80 percent of the height/width of the screen, and that's the canvas area.
2. `innerPanel` It has a width of 100 pixels and a maximum width of 50 pixels. The width of the area will be 50 pixels.
3. `innerPanel` It has a height of 50% of the height of the parent element.
4. `innerPanel` offset by 50 pixels over `Left` It's about the parent element. `X-области` will be: 10% of the screen width + 50 pixels.
5. `innerPanel` offset by 50 pixels over `Top` It's about the parent element. `Y-области` It will be 10% of the screen height + 50 pixels.<br>

Let's say our screen is the size. `1000x500`Then:<br>
The Domain `canvas`:
1. `X`: 1000 * 0.1 = 100px;
2. `Y`: 500 * 0.1 = 50px;
3. `Width`: 1000 * 0.8 = 800px;
4. `Height`: 500 * 0.8 = 400px;<br>

And then the field `innerPanel` It is calculated as follows:
1. `X`: `область-canvas-x` + `innerPanelStyleCanvas.Left` >>> `100px + 50px`.
2. `Y`: `область-canvas-y` + `innerPanelStyleCanvas.Top` >>> `50px + 50px`.
3. `Width` `Width = 100px`, `MaxWidth = 50px` >>> 50px;
4. `Height`: `область-canvas-Height * 0.5 = 400px * 0.5`.<br>

Result:
1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.

----

**Outer region** It's the element. **element** + Margin (but with the nuances described below).<br>

Modify the code earlier:
```csharp

// for the “hot code reboot” function in the development environment.

// method OnInitialize()

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();
    StyleLayoutChildCanvas innerPanelStyleCanvas = innerPanelStyle.Canvas();

    innerPanel.MaxWidth.Set(50f, 0f);
    innerPanelStyle.Width.Pixels = 100f;
    innerPanelStyle.Height.Precent = 0.5f;

    innerPanelStyleCanvas.Left.Pixels = 50f;
    innerPanelStyleCanvas.Top.Pixels = 50f;

    innerPanelStyle.Margin = new(
        pixels: true,
        left:   25f,

    Append(canvas);

```
The Domain `innerPanel`:
1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.<br>

The outer area shall be considered as follows:
1. `outer-X`: `X - Margin.Left`.
2. `outer-Y`: `Y - Margin.Top`.
3. `outer-Width`: `Width + Margin.Left + Margin.Right`.
4. `outer-Height`: `Height + Margin.Top + Margin.Bottom`.<br>

Outer region `innerPanel`
1. `outer-X`: `150px - 25px = 125px`.
2. `outer-Y`: `100px - 50px = 50px`.
3. `outer-Width`: `50px + 25px + 75px = 150px`.
4. `outer-Height`: `200px + 50px + 100px = 350px`.<br>

And here's the important thing: The size of the element that you see on the screen is always the size of the area (not the outside or the inside).<br>
The size of the external area only affects how much space the linker thinks the element occupies.<br>
In this case, the element will visually occupy `50x200px`But for the linkers (e.g. `UIExGrid`) - the element will occupy `150x350px`.<br>
If this element is in the `UIExGrid` in the cell, which must itself adjust to the size of the element in it - it will adjust to the size `150x350px`That is, the cell will be larger than the visible size of the element.

Small summing-up `Marign`:
1. `Margin.Top` and `Margin.Left`: enlarge the outer region and create a space between the right/left boundary of the outer region and the area of the element.
2. `Margin.Right` and `Margin.Bottom`: enlarge the outer region and create a space between the right/lower boundary of the outer region and the area of the element.<br>
Thus, `Margin` It does not change the size of the area of the element itself, it changes the space that the linker reserves around that area.

----

**Internal area of the element** This is the area where, according to the “opinion” of this element, the elements embedded in it should be located.<br>
By default. **element** and **perimeter** the same.<br>
The internal area is defined by means of `PaddingLeft`, `PaddingTop`, `PaddingRight`, `PaddingBottom`.<br>
There are no analogues of these fields in this library. `UIElement`These values should be used correctly directly from any `UIElement`.<br>

The library uses its own `Padding` in separate containers of the layout, but it is never specified directly `UIElement`.<br>

In addition, `PaddingLeft`, `PaddingTop`, `PaddingRight`, `PaddingBottom` Can be controlled automatically by the class `UIExElement`.<br>
See more information in Section 3: “Class” `UIExElement`».<br><br>

The Domain `innerPanel`:
1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.<br>

The interior area shall be considered as follows:
1. `inner-X`: `X + PaddingLeft`.
2. `inner-Y`: `Y + PaddingTop`.
3. `inner-Width`: `Width - PaddingLeft - PaddingRight`.
4. `inner-Height`: `Height - PaddingTop - PaddingBottom`.<br>

Suppose:
```csharp

innerPanel.PaddingTop = 20f;
innerPanel.PaddingRight = 30f;
innerPanel.PaddingBottom = 40f;
```

Then there's the interior `innerPanel`:
1. `inner-X`: `150px + 10px = 160px`.
2. `inner-Y`: `100px + 20px = 120px`.
3. `inner-Width`: `50px - 10px - 30px = 10px`.
4. `inner-Height`: `200px - 20px - 40px = 140px`.<br>

This part of the code indicates that the elements inside `canvas` They need to be centered.<br>
This means that the coordinates of the external area should be:
1. `outer-X`: `(ширина внутренней области canvas) / 2f - (ширина внешней области innerPanel) / 2f`.
2. `outer-Y`: `(высота внутренней области canvas) / 2f - (высота внешней области innerPanel) / 2f`.<br>

```csharp
        right:        10f,

```

The thing is that in this model layout `Margin.Right` and `Margin.Bottom` not cheat `X/Y` area of the element.<br>
They only affect the size of the outer area.<br>
So the coordinates in this example. `X/Y` The outside and the ordinary are the same.<br>

To facilitate the creation of `UIElement-оберток` class `UIExLayout` provides static methods `Wrap`:

```csharp
public static TUIElement Wrap<TUIElement>(UIElement element, bool stretch = false, bool center = false)
    where TUIElement : UIElement, new()
        => Wrap(element, new TUIElement(), stretch, center);

public static TUIElement Wrap<TUIElement>(UIElement element, TUIElement wrapElement, bool stretch = false, bool center = false)
    where TUIElement : UIElement
{
    if (stretch)
    {
        element.Width.Set(0f, 1f);
        element.Height.Set(0f, 1f);
    }

    if (center)
    {
        element.HAlign = 0.5f;
        element.VAlign = 0.5f;
    }

    wrapElement.Append(element);
    return wrapElement;
}
```

The method itself creates a wrapper for a given element and returns it.<br>
Now, let's replace the previous code with the Wrap method.

```csharp
// "UIPanel panel2 = new();" from the penultimate code, replace by:
UIPanel panel2 = new();
panel2.MarginTop = 10f;

var wrapElement = UIExLayout.Wrap<UIElement>(panel2, stretch: true, center: false);



// "stackPanel.Append(panel2);" from the penultimate code shall be replaced by:
stackPanel.Append(wrapElement);
```

What this code does:
1. Refers to the static method `Wrap` classUIExLayout'.
2. It is transmitted as a universal type. `UIElement`This is the type of user interface that our element will be wrapped into.
3. First argument:`panel2`- our `UIElement` Or an heir to be wrapped.
4. Second argument:`stretch: true`) - a flag indicating that it is necessary to stretch the object to be wrapped over the entire area of the wrapper. `true` - for `panel2` The values will be set: `Width.Set(0f, 1f)`, `Height.Set(0f, 1f)`.
5. Third argument:`center: false`) - a flag indicating that it is necessary to place the object to be wrapped in the center of the wrapper area. `true` - for `panel2` will determine the values `HAlign = 0.5f; VAlign = 0.5f`.

<h2 align="center">Method <code>Stretch()</code></h2>

Class `UIExLayout` implement `Stretch()`:
```csharp
public virtual void Stretch()

	Left.Set(0f, 0f);
	Height.Set(0f, 1f);
	Width.Set(0f, 1f);
}
```
As you can see from the code, this method simply stretches the container across the size of the entire parent area.<br>

Remember, the values that this method establishes are only used. **NOT.** So this method doesn't do anything, in the following situation (second call of the method):
```csharp

canvas.Stretch();

///////////////////////
```

1. `canvas` and `stackPanel` method `Stretch()`.

3. `stackPanel` inserted `canvas`which **NOT.** uses standard values `Top`, `Left`, `Width`, `Height`.
   - Accordingly, the method `Stretch` does nothing for `stackPanel`.
