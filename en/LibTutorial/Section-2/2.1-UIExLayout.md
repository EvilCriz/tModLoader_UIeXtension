<br>

The `UIExLayout` class is the base class for layout elements. It implements:

1. The lifecycle of element layout.
2. Container layout styles supported by any layout element.
3. Storage of child element layout styles and access to them.
4. Auxiliary static `Wrap` methods, which will be described in this article.
5. Optimization tools, some of which are delegated to external control (due to internal **tModLoader** limitations).

   <br>

* This article will cover these points, except:
* Point 1 — the layout lifecycle. It will be covered in a separate part of this section. You only need to understand the lifecycle if you plan to write your own layout element based on this library.
* Point 5 — optimization tools. They will be covered in a separate part of this section.
* Point 3 — will be partially covered in this article and partially in a separate part of this section.

<h2 align="center">Container and Child Element Layout Styles</h2>

The `UIExLayout` class defines the field:

```csharp
public Styles.StyleLayoutContainer StyleLayout;
```

This field contains the layout styles implemented by any layout container.<br>

The `Styles.StyleLayoutContainer` type has the following implementation:

```csharp
public class StyleLayoutContainer() : Base.StyleLayoutContainerBase
{
    public UIExOrientation Orientation = UIExOrientation.Vertical;
    public UIExAlignment JustifyContent = UIExAlignment.Auto;
    public UIExAlignment AlignItems = UIExAlignment.Auto;
}
```

* `Orientation` determines which axis is considered the main axis of the container and which is the cross axis.
* `JustifyContent` and `AlignItems` specify how elements are aligned along the main and cross axes. `UIExAlignment` can have the following values:

  * `Start`: alignment to the beginning of the main / cross axis.
  * `Center`: alignment to the center of the main / cross axis.
  * `End`: alignment to the end of the main / cross axis.
  * `Stretch`: stretches along the main / cross axis.
  * `Auto`: this value is used only by child elements of a container (see below). Using this value for `JustifyContent` and `AlignItems` is treated as `Start`.

---

The `Styles.StyleLayoutChild` class defines the layout styles for child elements of a container.

```csharp
public class StyleLayoutChild : Base.StyleLayoutChildBase
{
    public UIExAlignment JustifySelf = UIExAlignment.Auto;
    public UIExAlignment AlignSelf = UIExAlignment.Auto;
	
	public UIExThickness Margin = new();

	public bool WithoutLayout = false;

	public StyleDimension Width = default(StyleDimension);
	public StyleDimension Height = default(StyleDimension);
}
```

`JustifySelf` and `AlignSelf` determine how an element is aligned along the main / cross axis. We have already discussed the values of `UIExAlignment` above, except for `Auto`. For child elements of a container, this value is the key.<br>

If the container has `JustifyContent == UIExAlignment.Center`, this means that all elements inside the container will be centered along the main axis (the exact meaning of «center» depends on the layout element). This rule applies to all child elements whose `JustifySelf == UIExAlignment.Auto`.<br>

`Auto` for a child element means that it will inherit the container's value. Any other `JustifySelf` value overrides `JustifyContent` for that particular element.<br>

The situation is analogous for `AlignSelf` on the cross axis.<br>

We will discuss `Margin`, `Width`, and `Height` in more detail below.<br>

<h2 align="center">Excluding an Element from Layout</h2>

```csharp
public bool WithoutLayout = false;
```

This field determines whether the element will be ignored during layout.<br>
All methods of changing the size and position of such an element remain standard **tModLoader** behavior.<br>
For example, imagine that we are creating a panel for a Minesweeper game.

* There should be the main game panel, into which the game board, settings, etc. can be added.
* The game board itself.
* And the text `"GAME OVER"` displayed exactly in the center of the game board.

  <br>
  <em>Fig. 1.1. Layout of a simplified Minesweeper game</em>
</p>

```csharp
// The OnActivate() method is used here only for the
// "hot code reload" feature in the development environment.
// For a real interface, it would be more appropriate to use
// the OnInitialize() method.
public override void OnActivate()
{
    RemoveAllChildren();

    // A greatly simplified Minesweeper game layout.

    // Creates a panel occupying 60% of the screen and positioned in the center.
    UIPanel panel = new();
    Append(panel);

    // A method written for demonstration purposes. NOT defined in the library itself.
    SetPrecentSize(panel, left: 0.2f, top: 0.2f, width: 0.6f, height: 0.6f);


    /////////////////////////////////


    // Creates a 10x10 UniformGrid and adds buttons to it.
    // The Grid panel is placed inside panel and occupies width: 50%; height: 80% of panel.
    UIExUniformGrid grid = new();
    panel.Append(grid);

    SetPrecentSize(grid, left: 0.25f, top: 0.1f, width: 0.5f, height: 0.8f);

    int rows = 10, columns = 10;
    

    /////////////////////////////////


    // Specifies that the buttons added to the UniformGrid should occupy 100% of each cell.
    grid.StyleLayout.JustifyContent = UIExAlignment.Stretch;
    grid.StyleLayout.AlignItems = UIExAlignment.Stretch;

    for (int row = 0; row < rows; row++)
        for (int column = 0; column < columns; column++)
        {
            UIButton<string> button = new($"[{row},{column}]");
            grid.Append(button);
        }

    // Creates the text. It is added to the grid.
    UIText text = new("GAME OVER");
    text.TextColor = Color.DarkRed;
    StyleLayoutChild styleText = text.StyleLayoutChild();

    // Specifies that the UniformGrid should not control the layout of text.
    // This means that the tModLoader Canvas will be used.
    styleText.WithoutLayout = true;

    // Specifies that the text should be exactly in the center of the grid.
    text.HAlign = 0.5f;
    text.VAlign = 0.5f;
    grid.Append(text);
}
```

If you want to use only this library for positioning elements, `UIExCanvas` could be used for this task. In that case, part of the code can be replaced.<br>
This part of the code:

```csharp
// Creates the text. It is added to the grid.
UIText text = new("GAME OVER");
text.TextColor = Color.DarkRed;
StyleLayoutChild styleText = text.StyleLayoutChild();

// Specifies that the UniformGrid should not control the layout of text.
// This means that the tModLoader Canvas will be used.
styleText.WithoutLayout = true;

// Specifies that the text should be exactly in the center of the grid.
text.HAlign = 0.5f;
text.VAlign = 0.5f;
grid.Append(text);
```

Can be replaced with:

```csharp
UIExCanvas canvas = new();
canvas.Stretch();

UIText text = new("GAME OVER");
text.TextColor = Color.DarkRed;

canvas.StyleLayoutChild().WithoutLayout = true;

canvas.StyleLayout.JustifyContent = UIExAlignment.Center;
canvas.StyleLayout.AlignItems = UIExAlignment.Center;

canvas.Append(text);
grid.Append(canvas);
```

<h2 align="center">Position and Size of Child Elements</h2>

Regarding positions, you need to know the following:

* Layout elements never look at the `Left` and `Top` values of `UIElement`.
* Layout elements set these values while ignoring the values assigned before layout.<br>

<!-- -->

* Only one layout element allows absolute element coordinates to be specified: `UIExCanvas`.
* `UIExCanvas` allows **4** absolute coordinates to be specified using a special child-element style class.
* All other layout elements use completely different systems.<br>

<!-- -->

In summary:

* The `Left` and `Top` values of elements inside a layout container do not affect layout and, after layout, will most likely differ from their values before layout.<br>

---

Regarding sizes, you need to know the following:

* Layout elements never look at the `Width` and `Height` values of `UIElement`.
* Layout elements set these values while ignoring the values assigned before layout.<br>

<!-- -->

* Initial sizes are specified using `Width` and `Height` in `StyleLayoutChild`.
* These size values from the style class are used only by layout elements. Outside layout elements, they do nothing.
* `MinWidth`, `MaxWidth`, `MinHeight`, and `MaxHeight` work normally. These fields do not exist in `StyleLayoutChild`; their values are taken from `UIElement`.<br>

<!-- -->

Why does the layout system have separate, identical fields?

* Some layout elements simultaneously change sizes and perform layout based on the original element sizes.
* Therefore, a layout element can change the size, set the `Width` and `Height` fields defined in `UIElement`, and the original sizes will be lost during the next layout.
* As a result, the layout will produce completely different results with every iteration.
* Separate size fields were introduced to eliminate this problem.

<h2 align="center"><code>Margin</code>, <code>Padding</code>, <code>Stretch</code>, and the Three Element Areas</h2>

This section contains a detailed description of the library's layout model.
This information is especially important in three cases:

1. You plan to draw elements on the screen yourself (in that case, simply using `Left`, `Top`, `Width`, and `Height` will not be sufficient).
2. You plan to write your own layout element based on this library.
3. You want to understand the general principle by which a layout element positions elements (taking into account `Margin`, `Padding`, `Stretch`, its own area, and the areas of its elements).

Each element has 3 areas (the coordinates of the top-left corner + size):

1. The element area itself.
2. The outer area of the element.
3. The inner area of the element.<br>

All layout containers work **exclusively** with the outer area of an element.<br>
This is the most important thing you need to know when working with the layout elements of this library or creating your own.<br>
The container does not care about the normal or inner area of an element.
The container cares only about:

1. Its own inner area.
2. The outer areas of its child elements.

**The element area itself** is not simply `Left`, `Top`, `Width`, and `Height`.<br>
`Left` and `Top` are offsets of the element relative to the inner area of its parent.
After recalculation, `UIElement` stores the element area as follows:

1. `X` of the area: `X` of the parent's inner area (in absolute screen coordinates) + `Left` of the element.
2. `Y` of the area: `Y` of the parent's inner area (in absolute screen coordinates) + `Top` of the element.
3. `ActualWidth` of the area: `Clamp(Width, MinWidth, MaxWidth)`.
4. `ActualHeight` of the area: `Clamp(Height, MinHeight, MaxHeight)`.<br>

In other words, the element area consists of its absolute **X/Y** coordinates relative to the screen origin + the element size constrained by `Min` and `Max`.

---

**The element area itself (item 1)** is determined by the following algorithm in the layout elements of this library:

1. The size of the available space allocated by the layout element for placement is taken.
2. Based on the size of the allocated space and the values of (`Width`, `MinWidth`, `MaxWidth`, `Height`, `MinHeight`, `MaxHeight`), the element size is determined.
3. Based on the offset of the allocated space and the `Top` and `Left` values, the current element position is determined (relative to the screen origin, not the parent element).
   For example:

```csharp
// The OnActivate() method is used here only for the
// "hot code reload" feature in the development environment.
// For a real interface, it would be more appropriate to use
// the OnInitialize() method.
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Left.Precent = 0.1f;
    canvas.Top.Precent = 0.1f;
    canvas.Width.Precent = 0.8f;
    canvas.Height.Precent = 0.8f;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();
    StyleLayoutChildCanvas innerPanelStyleCanvas = innerPanelStyle.Canvas();

    innerPanel.MaxWidth.Set(50f, 0f);
    innerPanelStyle.Width.Pixels = 100f;
    innerPanelStyle.Height.Precent = 0.5f;

    innerPanelStyleCanvas.Left.Pixels = 50f;
    innerPanelStyleCanvas.Top.Pixels = 50f;

    canvas.Append(innerPanel);
    Append(canvas);
}
```

1. `canvas` starts at 10% of the screen height/width and has a size of 80% of the screen height/width. This is the canvas area.
2. `innerPanel` has a width of 100 pixels and a maximum width of 50 pixels. The area width will therefore be 50 pixels.
3. `innerPanel` has a height of 50% of the parent element's height.
4. `innerPanel` is offset by 50 pixels via `Left` relative to the parent element. Therefore, `X` of the area will be: 10% of the screen width + 50 pixels.
5. `innerPanel` is offset by 50 pixels via `Top` relative to the parent element. Therefore, `Y` of the area will be: 10% of the screen height + 50 pixels.<br>

Suppose our screen size is `1000x500`, then:<br>
The `canvas` area:

1. `X`: 1000 * 0.1 = 100px;
2. `Y`: 500 * 0.1 = 50px;
3. `Width`: 1000 * 0.8 = 800px;
4. `Height`: 500 * 0.8 = 400px;<br>

The `innerPanel` area is then calculated as follows:

1. `X`: `canvas-area-x` + `innerPanelStyleCanvas.Left` >>> `100px + 50px`.
2. `Y`: `canvas-area-y` + `innerPanelStyleCanvas.Top` >>> `50px + 50px`.
3. `Width`: `Width = 100px`, `MaxWidth = 50px` >>> 50px;
4. `Height`: `canvas-area-Height * 0.5 = 400px * 0.5`.<br>

Result:

1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.

---

**The outer area** of the element is **the element area** + Margin (with nuances described below).<br>

Let's modify the previous code:

```csharp
// The OnActivate() method is used here only for the
// "hot code reload" feature in the development environment.
// For a real interface, it would be more appropriate to use
// the OnInitialize() method.
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Left.Precent = 0.1f;
    canvas.Top.Precent = 0.1f;
    canvas.Width.Precent = 0.8f;
    canvas.Height.Precent = 0.8f;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();
    StyleLayoutChildCanvas innerPanelStyleCanvas = innerPanelStyle.Canvas();

    innerPanel.MaxWidth.Set(50f, 0f);
    innerPanelStyle.Width.Pixels = 100f;
    innerPanelStyle.Height.Precent = 0.5f;

    innerPanelStyleCanvas.Left.Pixels = 50f;
    innerPanelStyleCanvas.Top.Pixels = 50f;

    innerPanelStyle.Margin = new(
        pixels: true,
        left:   25f,
        top:    50f,
        right:  75f,
        bottom: 100f);

    canvas.Append(innerPanel);
    Append(canvas);
}
```

The `innerPanel` area:

1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.<br>

The outer area is calculated as follows:

1. `outer-X`: `X - Margin.Left`.
2. `outer-Y`: `Y - Margin.Top`.
3. `outer-Width`: `Width + Margin.Left + Margin.Right`.
4. `outer-Height`: `Height + Margin.Top + Margin.Bottom`.<br>

The outer area of `innerPanel`:

1. `outer-X`: `150px - 25px = 125px`.
2. `outer-Y`: `100px - 50px = 50px`.
3. `outer-Width`: `50px + 25px + 75px = 150px`.
4. `outer-Height`: `200px + 50px + 100px = 350px`.<br>

And here is an important point. The size of the element itself that you see on the screen is always the size of the **element area**, not the outer or inner area.<br>
The outer area only affects how much space the layout element considers the element to occupy.<br>
In this case, the element will visually occupy `50x200px`. But for layout elements (for example, `UIExGrid`), the element will occupy `150x350px`.<br>
If this element is located in a `UIExGrid` cell that automatically adjusts to the size of the element inside it, the cell will adjust to `150x350px`, meaning the cell will be larger than the visible element.

A short summary of `Margin`:

1. `Margin.Top` and `Margin.Left` increase the outer area and create space between the top/left boundary of the outer area and the element area.
2. `Margin.Right` and `Margin.Bottom` increase the outer area and create space between the right/bottom boundary of the outer area and the element area.<br>
   Thus, `Margin` does not change the size of the element area — it changes the amount of space reserved by the layout element around that area.

---

**The inner area of an element** is the area where, according to the element itself, its child elements should be placed.<br>
By default, the **element area** and **inner area** are identical.<br>
The inner area is defined using `PaddingLeft`, `PaddingTop`, `PaddingRight`, and `PaddingBottom`.<br>
There are no equivalents of these fields in this library (for `UIElement`). These values should be used directly on any `UIElement`.<br>

The library uses its own `Padding` in individual layout containers, but it is never assigned directly to a `UIElement`.<br>

In addition, `PaddingLeft`, `PaddingTop`, `PaddingRight`, and `PaddingBottom` can be controlled automatically by the `UIExElement` class.<br>
See the more detailed information in Section 3: «Class `UIExElement`».<br><br>

The `innerPanel` area:

1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.<br>

The inner area is calculated as follows:

1. `inner-X`: `X + PaddingLeft`.
2. `inner-Y`: `Y + PaddingTop`.
3. `inner-Width`: `Width - PaddingLeft - PaddingRight`.
4. `inner-Height`: `Height - PaddingTop - PaddingBottom`.<br>

Suppose:

```csharp
innerPanel.PaddingLeft = 10f;
innerPanel.PaddingTop = 20f;
innerPanel.PaddingRight = 30f;
innerPanel.PaddingBottom = 40f;
```

Then the inner area of `innerPanel` is:

1. `inner-X`: `150px + 10px = 160px`.
2. `inner-Y`: `100px + 20px = 120px`.
3. `inner-Width`: `50px - 10px - 30px = 10px`.
4. `inner-Height`: `200px - 20px - 40px = 140px`.<br>

Let's summarize with an example:

```csharp
// The OnActivate() method is used here only for the
// "hot code reload" feature in the development environment.
// For a real interface, it would be more appropriate to use
// the OnInitialize() method.
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Width.Precent = 1f;
    canvas.Height.Precent = 1f;

    canvas.PaddingLeft = 20f;
    canvas.PaddingTop = 40f;
    canvas.PaddingRight = 60f;
    canvas.PaddingBottom = 80f;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();
    StyleLayoutChildCanvas innerPanelStyleCanvas = innerPanelStyle.Canvas();

    innerPanel.MaxWidth.Set(50f, 0f);
    innerPanelStyle.Width.Pixels = 100f;
    innerPanelStyle.Height.Precent = 0.5f;

    innerPanelStyleCanvas.Left.Pixels = 50f;
    innerPanelStyleCanvas.Top.Pixels = 50f;

    innerPanelStyle.Margin = new(
        pixels: true,
        left:   15f,
        top:    25f,
        right:  35f,
        bottom: 45f);

    canvas.Append(innerPanel);
    Append(canvas);
}
```

In this example, `canvas` occupies 100% of the screen width and height. This is the area that is identical to its outer area.<br>

The inner area of `canvas`:

1. `inner-X`: `X == 0` + `PaddingLeft == 20px`.
2. `inner-Y`: `Y == 0` + `PaddingTop == 40px`.
3. `inner-Width`: `Width == screenWidth` - `PaddingLeft == 20px` - `PaddingRight == 60px`.
4. `inner-Height`: `Height == screenHeight` - `PaddingTop == 40px` - `PaddingBottom == 80px`.<br>

Result:

1. `inner-X`: `20px`.
2. `inner-Y`: `40px`.
3. `inner-Width`: `screenWidth - 100px`.
4. `inner-Height`: `screenHeight - 120px`.<br>

The `innerPanel` element area (not outer or inner) has 100% of the container's width and 100% of its height. But this is 100% of the `canvas` inner area.<br>
Therefore, the `innerPanel` area is equal to the inner area of `canvas`.<br>
But this is only true until `Margin` enters the calculation.<br>

The outer area of `innerPanel` is then calculated as follows:

1. `outer-X`: `canvas-inner-x - innerPanelStyle.Margin.Left`
2. `outer-Y`: `canvas-inner-y - innerPanelStyle.Margin.Top`
3. `outer-Width`: `canvas-inner-width + innerPanelStyle.Margin.Left + innerPanelStyle.Margin.Right`
4. `outer-Height`: `canvas-inner-height + innerPanelStyle.Margin.Top + innerPanelStyle.Margin.Bottom`<br>

Substituting the values:

1. `outer-X`: `20px - 15px`
2. `outer-Y`: `40px - 25px`
3. `outer-Width`: `screenWidth - 100px + 15px + 35px`
4. `outer-Height`: `screenHeight - 120px + 25px + 45px`<br>

Result:

1. `outer-X`: `5px`
2. `outer-Y`: `15px`
3. `outer-Width`: `screenWidth - 50px`
4. `outer-Height`: `screenHeight - 50px`<br>

And now the most important point. A layout element positions the **OUTER** area of its elements.

```csharp
// The OnActivate() method is used here only for the
// "hot code reload" feature in the development environment.
// For a real interface, it would be more appropriate to use
// the OnInitialize() method.
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Width.Precent = 1f;
    canvas.Height.Precent = 1f;
    canvas.StyleLayout.JustifyContent = UIExAlignment.Center;
    canvas.StyleLayout.AlignItems = UIExAlignment.Center;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();

    innerPanelStyle.Width.Pixels = 50f;
    innerPanelStyle.Height.Pixels = 50f;

    innerPanelStyle.Margin = new(
        pixels: true,
        top:    10f,
        left:   20f);

    canvas.Append(innerPanel);
    Append(canvas);
}
```

In this case:

```csharp
canvas.StyleLayout.JustifyContent = UIExAlignment.Center;
canvas.StyleLayout.AlignItems = UIExAlignment.Center;
```

This part of the code specifies that the elements inside `canvas` should be centered.<br>
This means that the coordinates of the outer area should be:

1. `outer-X`: `(width of the canvas inner area) / 2f - (width of the innerPanel outer area) / 2f`.
2. `outer-Y`: `(height of the canvas inner area) / 2f - (height of the innerPanel outer area) / 2f`.<br>

The center of the `innerPanel` outer area will therefore be exactly at the center.<br>

However, the normal `innerPanel` area starts at `outer-X - 20px` and `outer-Y - 10px`.<br>
This means that `innerPanel` will appear `20px` to the right and `10px` below the center on the screen.<br>

At the same time, if we specify:

```csharp
innerPanelStyle.Margin = new(
        pixels:       true, 
        right:        10f, 
        bottom:       20f);
```

we will see that the element is perfectly centered on the screen.<br>
The reason is that in this layout model, `Margin.Right` and `Margin.Bottom` do not change the `X/Y` coordinates of the element area.<br>
They only affect the size of the outer area.<br>
Therefore, in this example, the `X/Y` coordinates of the outer and normal areas coincide.<br>

**There is only one exception**: to obtain the **outer dimensions** of an element for which `Margin` from this library is defined (in `StyleLayoutChild.Margin`), always use the static method:

```csharp
public static CalculatedStyle GetForcedCalculatedOuterDimensions(
	UIElement element, 
	Styles.StyleLayoutChild style, 
	CalculatedStyle parentInnerDimensions)
{ /* ... */ }
```

This information is needed for anyone who plans to create their own layout elements based on this library.<br>

Each of these static methods accepts:

1. The object whose area you want to obtain.
2. Its `StyleLayoutChild` styles (`Margin` will be taken from them).
3. The amount of space allocated to the element (for example: for `UIExCanvas` and `UIExStackPanel`, the result of calling `GetInnerDimensions()` on the layout element is passed; for `UIExGrid`, the size of the individual cell containing the element is passed).

---

Fields `JustifyContent` / `AlignItems` (and all their equivalents) with the value `UIExAlignment.Stretch` also stretch the outer area of the element.<br><br>

If an element is stretched horizontally and its `Margin.Left.Pixels = 10f; Margin.Right.Pixels = 10f`, this means that the outer area will be stretched, while the normal area will be `10px` smaller on the left and right sides.<br>
The element will be stretched across the entire width, with a `10px` reduction on both sides of the horizontal axis.

---

<h2 align="center">Combining <code>tModLoader Canvas</code> and <code>UIExLayout</code> Layout Elements</h2>

The most important thing you need to know when using `UIExLayout` is that it does not support the use of the following `UIElement` fields:<br>

* `Left`;
* `Top`;
* `Width`;
* `Height`;
* `MarginTop`;
* `MarginLeft`;
* `MarginBottom`;
* `MarginRight`;
* `HAlign`;
* `VAlign`. <br>Using these values for elements inside a layout element will result in incorrect layout.

`StyleLayoutChild` defines its own fields for these `UIElement` values:

```csharp
public class StyleLayoutChild : Base.StyleLayoutChildBase
{
	/* ... */
	public UIExThickness Margin = new();
	/* ... */
}
```

`Margin` has the `UIExThickness` type. Its offsets are represented by the `StyleDimension` type:

```csharp
public StyleDimension Left = StyleDimension.Empty;
public StyleDimension Top = StyleDimension.Empty;
public StyleDimension Right = StyleDimension.Empty;
public StyleDimension Bottom = StyleDimension.Empty;
```

If any of the `Margin` values ​​are specified as percentages, they will be calculated as a percentage of the layout container's size.

<br>

`HAlign` and `VAlign` are not used in the form in which they are defined in **tModLoader**. Instead, the `JustifyContent`, `AlignItems`, `JustifySelf`, and `AlignSelf` mechanism is used; its operation was described above.

The following `UIElement` fields are used normally and have no equivalents in this library:

* `PaddingLeft`
* `PaddingRight`
* `PaddingTop`
* `PaddingBottom`
* `MinWidth`
* `MaxWidth`
* `MinHeight`
* `MaxHeight`<br><br>

A few more words about `PaddingLeft`, `PaddingRight`, `PaddingTop`, and `PaddingBottom`.<br>
Some **visual display styles** or **tModLoader element visual styles** control these values automatically.<br>
For more details, see Section 3: «Class `UIExElement`».

---

What should you do if you still want to use the standard `Margin`, `HAlign`, and `VAlign` values?
In this case, you can use a `UIElement` wrapper. Suppose we currently have the following code **WITHOUT** using these fields:

```csharp
UIPanel panel = new();
SetPrecentSize(panel, left: 0.2f, top: 0.2f, width: 0.6f, height: 0.6f);

UIExStackPanel stackPanel = new();
stackPanel.Stretch();
stackPanel.StyleLayout.JustifyContent = UIExAlignment.Stretch;
stackPanel.StyleLayout.Alignment = UIExAlignment.Stretch;

UIPanel panel1 = new();
UIPanel panel2 = new();
UIPanel panel3 = new();

Append(panel);

panel.Append(stackPanel);

stackPanel.Append(panel1);
stackPanel.Append(panel2);
stackPanel.Append(panel3);
```

In this case we have:

1. `UIPanel` (`panel`) sized at 80% of the window and positioned in the center of the screen.
2. `UIExStackPanel` (`stackPanel`) sized at 100%. It is placed inside `panel`.
3. `UIPanel` (`panel1`, `panel2`, `panel3`) sized at 33.(3)% of `stackPanel`. They are placed inside `stackPanel`.

Now suppose we want to set `MarginTop = 10f;` for `panel2`.
We can wrap it in a `UIElement` (or any derived class).

```csharp
// Replace "UIPanel panel2 = new();" from the previous code with:
UIPanel panel2 = new();
SetPrecentSize(panel2, 0f, 0f, 1f, 1f);
panel2.MarginTop = 10f;

UIElement wrapElement = new();
wrapElement.Append(panel2);



// Replace "stackPanel.Append(panel2);" from the previous code with:
stackPanel.Append(wrapElement);
```

Now the `UIExStackPanel` layout element will control the position and size of `wrapElement`, while `panel2` will be inside the wrapper and laid out using the standard **tModLoader** methods.

---

To simplify the creation of `UIElement` wrappers, the `UIExLayout` class provides static `Wrap` methods:

```csharp
public static TUIElement Wrap<TUIElement>(UIElement element, bool stretch = false, bool center = false)
    where TUIElement : UIElement, new()
        => Wrap(element, new TUIElement(), stretch, center);

public static TUIElement Wrap<TUIElement>(UIElement element, TUIElement wrapElement, bool stretch = false, bool center = false)
    where TUIElement : UIElement
{
    if (stretch)
    {
        element.Width.Set(0f, 1f);
        element.Height.Set(0f, 1f);
    }

    if (center)
    {
        element.HAlign = 0.5f;
        element.VAlign = 0.5f;
    }

    wrapElement.Append(element);
    return wrapElement;
}
```

The method creates a wrapper for the specified element and returns it.<br>
Now let's replace the previous code with the `Wrap` method.

```csharp
// Replace "UIPanel panel2 = new();" from the previous code with:
UIPanel panel2 = new();
panel2.MarginTop = 10f;

var wrapElement = UIExLayout.Wrap<UIElement>(panel2, stretch: true, center: false);



// Replace "stackPanel.Append(panel2);" from the previous code with:
stackPanel.Append(wrapElement);
```

What does this code do:

1. Calls the static `Wrap` method of the `UIExLayout` class.
2. `UIElement` is passed as the generic type. This is the user interface element that will wrap our element.
3. The first argument (`panel2`) is our `UIElement` or derived class that should be wrapped.
4. The second argument (`stretch: true`) is a flag indicating that the wrapped object should be stretched across the entire wrapper area. When `true`, the following values are assigned to `panel2`: `Width.Set(0f, 1f)`, `Height.Set(0f, 1f)`.
5. The third argument (`center: false`) is a flag indicating that the wrapped object should be positioned in the center of the wrapper area. When `true`, the following values are assigned to `panel2`: `HAlign = 0.5f; VAlign = 0.5f`.

---

<h2 align="center">The <code>Stretch()</code> Method</h2>

The `UIExLayout` class implements the `Stretch()` method:

```csharp
public virtual void Stretch()
{
	Top.Set(0f, 0f);
	Left.Set(0f, 0f);
	Height.Set(0f, 1f);
	Width.Set(0f, 1f);
}
```

As you can see from the code, this method simply stretches the container to the size of the entire parent area.<br>

Remember! The values set by this method are used only by **NON-layout elements**. Therefore, this method does nothing in the following situation (the second method call):

```csharp
UIExCanvas canvas = new();
Append(canvas);

canvas.Stretch();

///////////////////////

UIExStackPanel stackPanel = new();
canvas.Append(stackPanel);

stackPanel.Stretch();

```

1. `canvas` and `stackPanel` both called `Stretch()`.
2. `canvas` was added directly inside `UIState`, which uses the standard **tModLoader** positioning / sizing methods.

   * Therefore, the `Stretch` method works fully.
3. `stackPanel` was added inside `canvas`, which does **NOT** use the standard `Top`, `Left`, `Width`, and `Height` values.

   * Therefore, the `Stretch` method does nothing for `stackPanel`.

<h2 align="center">Displaying Auxiliary Layout Lines</h2>

The `UIExLayout` class adds the following fields:

```csharp
public bool ShowLayoutLines = false;
public float LayoutLinesThickness = 1f;
public Color LayoutLinesColor = Color.LightGray;
```

* `ShowLayoutLines` specifies that auxiliary lines should be displayed over the element after layout.
* `LayoutLinesThickness` is the size of the auxiliary lines. It is not used if `ShowLayoutLines == false`.
* `LayoutLinesColor` is the color of the auxiliary lines. It is not used if `ShowLayoutLines == false`.

  <br>

Although these fields are used by all layout containers, the principle by which they are drawn differs between different containers.<br>

```csharp
UIExStackPanel stackPanel = new();
UIExGrid grid = new();
stackPanel.ShowLayoutLines = true; // lines will be drawn as Rectangles() around the space allocated for each element.
grid.ShowLayoutLines = true; // lines will be drawn as a grid.
```

`UIExLayout` implements the following methods:

```csharp
public void SetLayoutLinesInfoForBranch(bool state, float? thickness = null, Color? color = null) { /* ... */ }
public void SetLayoutLinesInfoForTree(bool state, float? thickness = null, Color? color = null) { /* ... */ }
```

* `SetLayoutLinesInfoForBranch` sets the specified non-null values for the current element and all its descendants that inherit from `UIExLayout`.
* `SetLayoutLinesInfoForTree` finds the root parent element and calls `SetLayoutLinesInfoForBranch` on it.

<br>The lines **ARE NOT** part of the UI. They are drawn directly over `UIExLayout`.<br>
