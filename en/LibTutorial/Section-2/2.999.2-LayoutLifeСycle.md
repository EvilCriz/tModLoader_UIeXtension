<h2 align="center">The <code>UIElement</code> Lifecycle in tModLoader</h2>

Before moving on to the lifecycle of layout containers, we should discuss the layout lifecycle in **tModLoader**.<br>

1. The `Recalculate` method is called for the root element (`UIState`).
2. The `Recalculate` method calculates the 3 areas of the element (see the `UIExLayout` article for more information about element areas).
3. The `Recalculate` method then calls the `RecalculateChildren` method.
4. The `RecalculateChildren` method calls the `Recalculate` method for all child elements.<br>

Thus, **tModLoader** calls the `Recalculate` method for the entire element tree every frame.

---

<h2 align="center">The <code>UIExLayout</code> Lifecycle</h2>

The first thing `UIExLayout` does is interfere with the `UI` lifecycle in **tModLoader**:

```csharp
public abstract partial class UIExLayout : UIExElement
{
    private bool _pauseRecalculateChildren = false;

    public override void Recalculate()
    {
        _pauseRecalculateChildren = true;
        base.Recalculate();
        _pauseRecalculateChildren = false;
        RecalculateLayout();
        RecalculateChildren();
    }


    public override void RecalculateChildren()
    {
        if (_pauseRecalculateChildren)
            return;

        base.RecalculateChildren();
    }
}
```

As you can see, `UIExLayout` adds a special flag that blocks calls to `Recalculate` for child elements.<br>

Thus, the lifecycle is now as follows:

1. Setting the `_pauseRecalculateChildren = true` flag, which prevents the execution of the `RecalculateChildren` method.
2. `base.Recalculate` - recalculation of the container's 3 areas.
3. `base.Recalculate` calls `RecalculateChildren`, but the call to this method is blocked by the `_pauseRecalculateChildren` flag.
4. Setting the `_pauseRecalculateChildren = false` flag, which allows the execution of the `RecalculateChildren` method.
5. Recalculation of the entire layout in the `RecalculateLayout` method.
6. Calling `RecalculateChildren`.<br>

Now:

1. The 3 areas of the container are recalculated first.
2. The elements inside the container are laid out.
3. The 3 areas of all elements are recalculated after layout.

<h3 align="center">The <code>RecalculateLayout</code> Method</h3>

```csharp
protected virtual void RecalculateLayout()
{
    // stage 1:
    var innerDimension = GetInnerDimensions();
    if (innerDimension.Width == 0f && innerDimension.Height == 0f)
        return;

    // stage 2:
    if (IsLayoutPreparation())
        return;

    // stage 3:
    if (_remainingRecalculateLayoutDelayMs > 0)
        return;

    // stage 4:
    UpdateStyleLayoutChildArray();

    // stage 5:
    if (!IsLastLayoutInfoChanged())
        return;

    // stage 6:
    BeginLayoutContext();

    try
    {
        // stage 7:
        PreRefreshLayout();

        // stage 8:
        RefreshLayout();

        // stage 9:
        PostRefreshLayout();

        // stage 10:
        ApplyLayout();

        // stage 11:
        RefreshLayoutDebugLines();
    }
    catch(System.Exception)
    {
        throw new System.Exception("[UIeXtension] RecalculateLayout Exception");
    }
    finally
    {
        // stage 12:
        EndLayoutContext();
    }

    // stage 13:
    UpdateLastLayoutInfo();

    // stage 14:
    int? recalculateLayoutDelayMsState = GetRecalculateLayoutDelayMsState(this);
    _remainingRecalculateLayoutDelayMs =
        recalculateLayoutDelayMsState is not null
            ? (int)recalculateLayoutDelayMsState
            : RecalculateLayoutDelayMs;
}
```

This method defines the entire layout lifecycle.<br>
General stages:

1. Check that the container has a size. Otherwise, exit the method.
2. Check that the container is not in the preparation state (see the previous article). Otherwise, exit the method.
3. Check that the container does not have an active delay before layout (see the previous article). Otherwise, exit the method.
4. Update all styles of the elements nested inside the container.
5. Check that the information has changed since the last layout (see the previous article). Otherwise, exit the method.
6. Prepare temporary data that is used only during a single layout.
7. Preliminary layout algorithm.
8. Main layout algorithm.
9. Layout algorithm after the main stage.
10. Apply the temporary data to the elements (setting `Width`, `Height`, `Top`, `Left` for child elements).
11. Algorithm for calculating auxiliary lines.
12. Release temporary data that is used only during layout.
13. Save the latest data after layout (see the previous section).
14. Update the minimum delay before the next layout.<br>

* Stage 1: a simple check.
* Stages 2-3: covered in the previous article.
* Stage 4: retrieving all styles of child elements and storing them in `private Styles.StyleLayoutChild[] _styleLayoutChildArray;`.
* Stage 5: covered in the previous article.
* Stage 6: covered separately below.
* Stages 7-9: the algorithms at these stages of the layout lifecycle are defined by each layout container itself.
* Stage 10: covered separately below.
* Stage 11: the algorithm for calculating auxiliary lines is defined by each layout container itself.
* Stage 12: covered separately below.
* Stage 13: covered in the previous article.
* Stage 14: see the last lines of the code above and the previous article.

<h3 align="center">Stages 6, 12: <code>BeginLayoutContext</code> and <code>EndLayoutContext</code></h3>

This method prepares/releases temporary data that is relevant only during the layout lifecycle.<br>
`UIExLayout` prepares data that is used by all layout containers.<br>
Each layout container separately prepares/releases its own data.<br><br>

```csharp
protected List<UIElement> _elementsContext = null;

protected List<RectangleLayoutContext> _rectangleContexts = null;

protected List<Styles.StyleLayoutChild> _styleElementsContexts = null;

protected CalculatedStyle _innerDimensionsContext;

protected List<CalculatedStyle> _elementsOuterDimensionsContext = null;

protected List<CalculatedStyle> _elementsDimensionsContext = null;
```

* `_elementsContext` - a list of child elements that participate in layout (those whose `StyleLayoutChild().WithoutLayout == false`)
* `_rectangleContexts` - a list of `RectangleLayoutContext` objects to which the size and offset of elements will be assigned during layout.
* `_styleElementsContexts` - a list of styles of the elements that participate in layout.
* `_innerDimensionsContext` - the inner area of the layout container.
* `_elementsOuterDimensionsContext` - a list of outer areas of the elements that participate in layout.
* `_elementsDimensionsContext` - a list of areas of the elements that participate in layout.<br>

`_styleElementsContexts`, `_styleElementsContexts`, `_elementsOuterDimensionsContext`, `_elementsDimensionsContext` have a list size equal to `_elementsContext.Count`.<br>
All indices match.<br><br>

* For all elements in `_elementsContext`, the `Top` and `Left` values are set to `StyleDimension.Empty` in `BeginLayoutContext`.<br>

<!-- -->

* `_rectangleContexts[i].Width` and `_rectangleContexts[i].Height` have `_elementsContext[i].Width` and `_elementsContext[i].Height` by default, calculated in pixels.
* `_rectangleContexts[i].Index = i`.<br><br>

`RectangleLayoutContext` has the following methods:

```csharp
public CalculatedStyle GetCalculatedStyle()
    => new(Left, Top, Width, Height);

public LayoutDebugRectangle GetLayoutDebugRectangle()
    => new(Left, Top, Width, Height);
```

<br>

In the `EndLayoutContext` method, all lists are set to `null`.

<h3 align="center">Stage 10: applying temporary data to elements</h3>

```csharp
protected virtual void ApplyLayout()
{
    foreach (var rectContext in _rectangleContexts)
        ApplyElementLayout(rectContext);
}

protected virtual void ApplyElementLayout(RectangleLayoutContext rectContext)
{
    UIElement element = _elementsContext[rectContext.Index];

    element.Top.Set(rectContext.Top, 0f);
    element.Left.Set(rectContext.Left, 0f);
    element.Width.Set(rectContext.Width, 0f);
    element.Height.Set(rectContext.Height, 0f);
}
```

At this stage, the following values are assigned to all elements that participate in layout:

* `Left`;
* `Top`;
* `Width`;
* `Height`.<br>

All values are taken from `_rectangleContexts`.
