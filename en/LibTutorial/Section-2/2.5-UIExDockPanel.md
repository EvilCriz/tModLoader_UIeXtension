`UIExDockPanel` This is the container of the layout, which **consistently** Docks child elements to one of the five sides of the available area:
- `Left`
- `Right`
- `Top`
- `Bottom`<br>

The remaining place is also considered a separate party: `Fill`.<br>
It takes up all the remaining available space after calculating the previous sides.<br>

`UIExDockPanel` It can be conventionally represented as two levels of layout:
1. First level: sequential allocation of the area `Left`, `Right`, `Top`, `Bottom` and `Fill`;
2. The second level: each side independently assembles the elements docked to it according to rules that are almost identical. `UIExStackPanel`.<br>

For each element (except for the 1st exception, which is later mentioned), we specify the side to which we want to dock it.<br>
But the key when working with this linker is the order of adding elements to the container.<br>

Let’s say we have 4 buttons that we docked to the side in relation to the name of the button and added to the linker in the following order:
1. `buttonTop`.
2. `buttonBottom`
3. `buttonLeft`
4. `buttonRight`<br>

The result of this you observed in the image above.<br>

But now we change the order of addition, and the buttons themselves will remain docked to the same sides, but the order of adding them to the container will be as follows:
1. `buttonLeft`
2. `buttonTop`.
3. `buttonBottom`
4. `buttonRight`<br>

From such a change in the order of addition of elements, we will see the following result:

----

The component does the following:
1. Remembers to which side the first element was docked; the second element, etc. For example:
   - The first is to the left side.
   - the second to the left side;
   - The third is to the right side.
   - the fourth to the left side;
   - Five to the underside.
2. Remembers the list of parties without repetition in the same order. Example (according to paragraph 1):
   - left-hand side;
   - right-hand side;
   - The bottom side.
3. Alternately allocates the size of each of the parties based on the list of claim 2 and the algorithm below.<br>

The dimensions of the side are defined as follows:
1. Height of the sides `Left` and `Right`The height of the free space in the container.
2. Breadth of sides `Left` and `Right`: the width of the largest outer region of the elements docked to this side.
3. Breadth of sides `Top` and `Bottom`The width of the free space in the container.
4. Height of the sides `Top` and `Bottom`: the height of the largest outer region of the elements docked to this side.<br>

After the area of the first added side is calculated, the area is excluded from the free space of the container.<br>
In an example from the previous image, a button docked to the left side was added first.<br>
This is what the free space looks like. `UIExDockPanel` After adding the first (left) side:

<h2 align="center">Styles. <code>UIExDockPanel</code></h2>

Basic style of arrangement of elements StyleLayoutContainer:
```csharp
public partial class StyleLayoutContainer : Base.StyleLayoutContainerBase
{
    public Enums.UIExOrientation Orientation = Enums.UIExOrientation.Vertical;
    public Enums.UIExAlignment JustifyContent = Enums.UIExAlignment.Auto;
    public Enums.UIExAlignment AlignItems = Enums.UIExAlignment.Auto;
}
```

- `Orientation`: defines the main axis **FILL** The side on which the elements will align within it.
  - For the parties `Left` and `Right` The orientation is always vertical.
  - For the parties `Top` and `Bottom` The orientation is always horizontal.
- `JustifyContent`: alignment of elements along the main axis (works for all sides; it is possible to override this value for a particular side and/or a particular element).
- `AlignItems`: alignment of elements along a transverse axis (works for all sides; it is possible to override this value for a particular side and/or a particular element).<br><br>

- Woo `Left`, `Right`, `Top` and `Bottom` The direction of the layout is clearly determined by the side itself.<br>
- `Fill` It does not have a fixed direction, so its orientation is defined by `StyleLayout.Orientation`.<br>

Levelling types:
```csharp
public enum UIExAlignment : byte
{
    Auto,
    Start,
    Center,
    End,
    Stretch
}
```

- `Auto`similarly `Start`Used by nested elements and/or parties.
- `Start`: alignment of the elements at the start of the side axis (top/left).
- `Center`: alignment of elements in the center of the axis of the side.
- `End`: alignment of elements at the end of the side axis (bottom/right).
- `Stretch`: stretching of the element along the whole axis of the side (net of) `Margin`).

----

Basic styles of child elements `StyleLayoutChild`:
```csharp
public partial class StyleLayoutChild : Base.StyleLayoutChildBase
{
    public Enums.UIExAlignment JustifySelf = Enums.UIExAlignment.Auto;
    public Enums.UIExAlignment AlignSelf = Enums.UIExAlignment.Auto;
    public UIExThickness Margin = new();
	public StyleDimension Width = default(StyleDimension);
    public StyleDimension Height = default(StyleDimension);
}
```
- Field. `JustifySelf` for child elements any value other than the value `Stretch` They're going to be ignored. `Auto` means that the value will be controlled by the container/party.
- Field. `AlignSelf` redefine `AlignItems` for a particular nested element. `Auto` means that the value will be controlled by the container/party.
- Field. `Margin` is taken into account in the arrangement of the element and in determining the size of the external area occupied by it.
- Fields `Width` and `Height` This article is described in detail in the first article of this section.

```csharp
public class SideStyle : Base.StyleBase
```

- `Padding`: indentations from the edges of the side to the designated position for the elements within the side.
- `JustifyContent`: aligning the elements along the main axis. Overrides the value `JustifyContent` Container style class for that particular party. `Auto` This means that the value will be controlled by the container.
- `AlignItems`: aligning the elements along the transverse axis. Overrides the value `AlignItems` Container style class for that particular party. `Auto` This means that the value will be controlled by the container.
- `Spacing`: is responsible for the space between the elements inside the side (the space between the elements on the main axis).
- `Reverse`: indicates that the elements of the party must be in reverse order.<br>

To get style `UIExDockPanel` use the method `DockPanel()` field `StyleLayout`:
```csharp

```

1. Lower.

3. Upper.
4. Right.

If we changed the order of adding the code, the order of allocation of space to the parties would also change.<br>
Except for the elements `Fill`.<br>
The order of addition of elements c `Side == Fill` does not affect the order of calculation of the parties.<br>
`Fill` always calculated after `Left`, `Right`, `Top` and `Bottom` And it takes up the rest of the space.<br>
That is, if we move the code responsible for adding elements to the remaining space to the very beginning, the result of the layout will not change.
