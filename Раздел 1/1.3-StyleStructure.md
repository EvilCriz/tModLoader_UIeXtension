<h1 align="center">Структура стилей</h1>

Стили в данной библиотеке делятся на 3 вида:
1. Стили визуального отображения.
2. Стили компоновки контейнера.
3. Стили компоновки отдельного элемента.

<br>

- **Стили визуального отображения** - это все стили, которые отвечают всю визуальную часть, кроме расположения элемента (цвет, форма, обводка и т.п.).

<br>

- **Стили компоновки контейнера** - это все стили, которые используют только компоновщики элементов (*UIExStackPanel*, *UIExDockPanel*, *UIExGrid* и т.п.). Они содержат общие правила о том, как располагать элементы внутри себя.

<br>

- **Стили компоновки отдельного элемента** - это все стили, которые использует компоновщик элементов, по отношению к отдельному *UIElement*. Более подробно это будет разбираться в разделе, посвященному компоновке элементов.

----

В данной статье не будут рассматриваться отдельные классы стилей. Каждый подобный класс связан со своим `UIExElement` (`UIExLayout` для стилей компоновки) и будут рассматриваться совместно с этими элементами в следующих разделах.

----

Самая сложная часть данной библиотеки - это разобраться в том, как же структурированы стили. Сложность связана с тем, что стили для разных элементов разделены по разным классам. 
Например, класс `UIExStackPanel` будет иметь у себя сразу два стиля компоновки: класса `StyleLayoutContainer` и класса `StyleLayoutContainerStackPanel`.

```csharp
UIExStackPanel stackPanel = new UIExStackPanel();
stackPanel.StyleLayout.ShowLyaoutLines = true;
stackPanel.StyleLayoutStackPanel.Orientation = Enums.Orientation.Horizontal;
```
Как видно в данном примере, используются два разных поля у объекта `stackPanel`:
- Поле `StyleLayout` имеет тип `StyleLayoutContainer` и определено у базового класса `UIExLayout`.
- Поле `StyleLayoutStackPanel` имеет тип `StyleLayoutContainerStackPanel` и определено в самом классе `UIExStackPanel`.

Таким образом у каждого элемента есть свой стиль (если он его определяет) и все стили базовых классов (если они их определяют).

----

Я думаю, вы уже понимаете, в чем сложность. Есть 3 типа стилей, каждых может быть по несколько штук. Как вообще определить, сколько стилей какой класс определяет? Какой тип данных у каждого из них? Как называется поле внутри `UIExElement`/`UIExLayout`?

Попытаемся выстроить систему. Начнем с `UIExElement` и всех его дочерних элементов, которые **НЕ** являются элементами компоновки.
Тут все становится сразу проще, так как у таких элементов только 1 тип стилей: **стили визуального отображения**.

----

У нас есть базовый класс `UIExElement`. У него есть поле `StyleDisplayElement` типа данных `StyleVisualElement`.

Теперь возьмем класс `UIExButton` (`class UIExButton : UIExElement { /* ... /* }`). У данного класса будут следующие стили:
- Поле `StyleDisplayElement` типа данных `StyleVisualElement`, который он унаследовал от `UIExElement`.
- Поле `StyleDisplayButton` типа данных `StyleVisualButton`, который он определяет.

<br>

Давайте представим теперь, что у нас есть еще вот такой класс:
`class UIExScaleButton : UIExButton { /* ... */ }`. У данного класса будут следующие стили:
- Поле `StyleDisplayElement` типа данных `StyleVisual`, который он унаследовал от `UIExElement`.
- Поле `StyleDisplayButton` типа данных `StyleVisualButton`, который он унаследовал от `UIExButton`.
- Поле `StyleDisplayScaleButton` типа данных `StyleVisualScaleButton`, который он определяет.

<br>

Вы можете заметить, что выстраивается система названий:
- `UIExElement` —— поле `StyleDisplayElement` —— `class StyleVisualElement`
- `UIExButton` —— поле `StyleDisplayButton` —— `class StyleVisualButton`
- `UIExScaleButton` —— поле `StyleDisplayScaleButton` —— `class StyleVisualScaleButton`

<br>

Как видно, система следующая: `UIEx_NAME` —— поле `StyleDisplay_NAME` —— `class StyleVisual_NAME`

<br>

Хорошо, а если у нас есть элементы:
- `class UIExExampleElement : UIElement { /* ... */ }`
- `class UIExExampleButton : UIExExampleElement { /* ... *? }`
- `var button = new UIExExampleButton()`

<br>

По системе у `UIExExampleButton` должны быть следующие поля:
- `StyleDisplayElement` —— `class StyleVisualElement`
- `StyleDisplayExampleElement` —— `class StyleVisualExampleElement`
- `StyleDisplayExampleButton` —— `class StyleVisualExampleButton`

Но что, если класс `UIExExampleElement` или `UIExExampleButton` не определяют своего стиля? Как это выяснить?

Есть множество способов:
1. В каждом классе есть перегрузка конструктора, которая принимает в себя все **стилей визуального отображения**, которые данный класс использует. Рекомендуемый способ. В конструкторе вы увидите все типы данных и все названия полей.
2. Ввести `button.StyleDisplay`. Так как все названия полей **стилей визуального отображения** начинаются со `StyleDisplay`, то среда разработки вам покажет все поля, которые начинаются со `StyleDisplay` определенные в данном классе.
3. Посмотреть всю ветку наследования, и определить, какие стили определяют дочерние классы.

----

Первой темой была затронута - тема **стилей визуального отображения**, потому что эти стили могут быть у любого элемента данной библиотеки. Но есть еще **стили компоновки контейнера**, которые есть только у элементов компоновки (наследники `UIExLayout`).

Система тут очень похожа:
- `UIExLayout` —— поле `StyleLayout` —— `class StyleLayoutContainer`
- `UIExStackPanel` —— поле `StyleLayoutStackPanel` —— `class StyleLayoutContainerStackPanel`
- *. . .*
- `UIEx_Name` —— поле `StyleLayout_Name` —— `class StyleLayoutContainer_Name`

Как видите система **стилей компоновки контейнера** очень похожа на систему **стилей визуального отображения**.

----

И последний этап: **стили компоновки отдельного элемента**

Эта система практически идентична системе **стилей компоновки контейнера**
Если там система быал такой:
- `UIEx_Name` —— поле `StyleLayout_Name` —— `class StyleLayoutContainer_Name`

То в данном случае система будет следующей:
- `UIEx_Name` —— **НЕТ** —— `class StyleLayoutChild_Name`

Как видите, изменения два:
1. UIEx_Name не определяет поле для **стиля компоновки отдельного элемента**. Стили для потомком элемента компоновки хранятся совершенно по другому, и это будет рассматриваться в разделе, который посвящен элементам компоновки.
2. `class StyleLayoutCONTAINER_Name` => `class StyleLayoutCHILD_Name`. Класс стилей просто меняет слово `Container` на `Child`.

----

Вся эта система может оказаться сложной при первом ознакомлении. Но она довольно быстро запоминается. В последующий разделах стили будут использоваться везде и всегда, и этот материал очень быстро усвоиться.
Я выбрал данный подход к созданию стилей для избегания путаницы. Чтобы пользователь данной библиотеки мог всегда точно знать, какие конкретно стили данной библиотеки поддерживает тот или иной элемент пользовательского интерфейса.
При этом, чтобы ему не приходилось копаться в рамках одного класса, перебирая все его поля и свойства, пытаясь найти все стили. При данном подходе они все четко рассортированы по классам, и все стили каждой группы находятся в одном месте.
