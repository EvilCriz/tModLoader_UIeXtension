<h2 align="center">життєвий цикл <code>UIElement</code> Увійти tModLoader</h2>

Перед тим як приступити до життєвого циклу посилань, слід поговорити про життєвий цикл макета в **tModLoader**.<br>

1. Для кореневого елемента (`UIState`) метод називається `Recalculate`.
2. Методика `Recalculate` розраховує 3 райони елемента (для отримання більш детальної інформації про область елемента див. статтю) `UIExLayout`).
3. Далі метод `Recalculate` методологія `RecalculateChildren`.
4. Методика `RecalculateChildren` методологія `Recalculate` для всіх дитячих елементів.<br>

Так, **tModLoader** методологія `Recalculate` Для всього дерева елементів кожен каркас.

----

<h2 align="center">життєвий цикл <code>UIExLayout</code></h2>

По-перше, він робить. `UIExLayout` - перешкоджає життєвому циклу `UI` Увійти **tModLoader**:
```csharp
public abstract partial class UIExLayout : UIExElement
{
    private bool _pauseRecalculateChildren = false;

    public override void Recalculate()
    {
        _pauseRecalculateChildren = true;
        base.Recalculate();
        _pauseRecalculateChildren = false;
        RecalculateLayout();
        RecalculateChildren();
    }


    public override void RecalculateChildren()
    {
        if (_pauseRecalculateChildren)
            return;

        base.RecalculateChildren();
    }
}
```
Як ви можете побачити, `UIExLayout` Додати спеціальний прапор, щоб заблокувати дзвінок. `Recalculate` на дитячих елементах.<br>

Цикл життя тепер:
1. Розміщення прапора `_pauseRecalculateChildren = true`заборона виконання виконання `RecalculateChildren`.
2. `base.Recalculate` Регуляція 3-х зон контейнера.
3. `base.Recalculate` рогоносець `RecalculateChildren`Цей метод заблокований прапором. `_pauseRecalculateChildren`.
4. Розміщення прапора `_pauseRecalculateChildren = false`Дозвіл на виконання методу `RecalculateChildren`.
5. Рекультивація всього макета в методі `RecalculateLayout`.
6. Завдання `RecalculateChildren`.<br>

Зараз:
1. По-перше, 3 райони контейнера перераховуються.
2. Елементи всередині контейнера зібрані.
3. Відтворено 3 зони всіх елементів після макета.

<h3 align="center">Методика <code>RecalculateLayout</code></h3>

```csharp
protected virtual void RecalculateLayout()
{
    // етап 1:
    var innerDimension = GetInnerDimensions();
    if (innerDimension.Width == 0f && innerDimension.Height == 0f)
        return;

    // етап 2:
    if (IsLayoutPreparation())
        return;

    // етап 3:
    if (_remainingRecalculateLayoutDelayMs > 0)
        return;

    // етап 4:
    UpdateStyleLayoutChildArray();

    // етап 5:
    if (!IsLastLayoutInfoChanged())
        return;

    // етап 6:
    BeginLayoutContext();

    try
    {
        // етап 7:
        PreRefreshLayout();

        // етап 8:
        RefreshLayout();

        // етап 9:
        PostRefreshLayout();

        // крок 10:
        ApplyLayout();

        // етап 11:
        RefreshLayoutDebugLines();
    }
    catch(System.Exception)
    {
        throw new System.Exception("[UIeXtension] RecalculateLayout Exception");
    }
    finally
    {
        // крок 12:
        EndLayoutContext();
    }

    // крок 13:
    UpdateLastLayoutInfo();

    // крок 14:
    int? recalculateLayoutDelayMsState = GetRecalculateLayoutDelayMsState(this);
    _remainingRecalculateLayoutDelayMs =
        recalculateLayoutDelayMsState is not null
            ? (int)recalculateLayoutDelayMsState
            : RecalculateLayoutDelayMs;
}
```

Цей метод визначає весь життєвий цикл макета.<br>
Загальні етапи:
1. Перевірити, що контейнер є розміром, інакше це вихід з методу.
2. Перевірити, що контейнер не в стані підготовки (див. попередній статті), інакше - вихід з методу.
3. Перевірити, що контейнер не має дійсної затримки до макета (див. попередній статті).
4. Оновлення всіх стилів елементів, вбудованих в контейнер.
5. Перевірити, що інформація змінилася з останнього макета (див. попередній статті).
6. Підготовка тимчасових даних, які використовуються тільки під час одного макета.
7. Алгоритм попереднього макета.
8. Базовий алгоритм макета.
9. Алгоритм макета після основного етапу.
10. Застосування тимчасових даних до елементів (Встановлення дитячих предметів) `Width`, `Height`, `Top`, `Left`).
11. Алгоритм розрахунку допоміжних ліній.
12. Видача тимчасових даних, які використовуються тільки при плануванні.
13. Запис останніх даних після макета (див. попередній розділ).
14. Оновити мінімальну затримку до наступного макета.<br>

- Етап 1: простий тест.
- Етап 2-3: обговорення у попередній статті.
- Етап 4: Отримання всіх стилів приглушених елементів і збереження їх в `private Styles.StyleLayoutChild[] _styleLayoutChildArray;`.
- Крок 5: обговорення у попередній статті.
- Крок 6: обговорювалися окремо нижче.
- Крок 7-9: Алгоритми на цих стадіях життєвого циклу макета визначається кожним посиланнямером.
- Крок 10: обговорювалися окремо нижче.
- Крок 11: Алгоритм розрахунку допоміжного рядка визначає себе кожного посилання.
- Крок 12: обговорюється окремо нижче.
- Крок 13: обговорення у попередній статті.
- Крок 14: Переглянути останні рядки коду вище і попередню статтю.

<h3 align="center">Етап 6, 12: <code>BeginLayoutContext</code> і <code>EndLayoutContext</code></h3>

Цей метод генерує/випускає тимчасові дані, які є тільки актуальними під час життєвого циклу макета.<br>
`UIExLayout` Приготуйте дані, які використовуються всіма посиланнями.<br>
Кожен ланцюжок окремо готує / випускає свої дані.<br><br>

```csharp
protected List<UIElement> _elementsContext = null;

protected List<RectangleLayoutContext> _rectangleContexts = null;

protected List<Styles.StyleLayoutChild> _styleElementsContexts = null;

protected CalculatedStyle _innerDimensionsContext;

protected List<CalculatedStyle> _elementsOuterDimensionsContext = null;

protected List<CalculatedStyle> _elementsDimensionsContext = null;
```

- `_elementsContext` список дитячих елементів, які беруть участь у макеті (які мають поле) `StyleLayoutChild().WithoutLayout == false`)
- `_rectangleContexts` - список `RectangleLayoutContext`, які будуть надані розміри і зміщення елементів під час планування.
- `_styleElementsContexts` - список стилів елементів, які беруть участь у макеті.
- `_innerDimensionsContext` - інтер'єрна зона джгута.
- `_elementsOuterDimensionsContext` Перелік зовнішніх зон елементів, які беруть участь у макеті.
- `_elementsDimensionsContext` Перелік зон елементів, які беруть участь у макеті.<br>

`_styleElementsContexts`, `_styleElementsContexts`, `_elementsOuterDimensionsContext`, `_elementsDimensionsContext` мати розмір списку, що дорівнює `_elementsContext.Count`.<br>
Всі індекси матч.<br><br>

- Всі елементи `_elementsContext` Увійти `BeginLayoutContext` фіксація `Top`, `Left` Про нас `StyleDimension.Empty`.<br>
<!-- -->
- `_rectangleContexts[i].Width` і `_rectangleContexts[i].Height` За замовчуванням `_elementsContext[i].Width`, `_elementsContext[i].Height` Вони піксельні.
- `_rectangleContexts[i].Index = i`.<br><br>

`RectangleLayoutContext` має методи:
```csharp
public CalculatedStyle GetCalculatedStyle()
    => new(Left, Top, Width, Height);

public LayoutDebugRectangle GetLayoutDebugRectangle()
    => new(Left, Top, Width, Height);
```
<br>

У методі `EndLayoutContext` Всі списки вказані значення. `null`.

<h3 align="center">Крок 10: Застосування часових даних до елементів</h3>

```csharp
protected virtual void ApplyLayout()
{
    foreach (var rectContext in _rectangleContexts)
        ApplyElementLayout(rectContext);
}

protected virtual void ApplyElementLayout(RectangleLayoutContext rectContext)
{
    UIElement element = _elementsContext[rectContext.Index];

    element.Top.Set(rectContext.Top, 0f);
    element.Left.Set(rectContext.Left, 0f);
    element.Width.Set(rectContext.Width, 0f);
    element.Height.Set(rectContext.Height, 0f);
}
```

На даному етапі всі елементи, які беруть участь у макеті, встановлюють значення:
- `Left`;
- `Top`;
- `Width`;
- `Height`.<br>

Всі значення приймаються з `_rectangleContexts`.
