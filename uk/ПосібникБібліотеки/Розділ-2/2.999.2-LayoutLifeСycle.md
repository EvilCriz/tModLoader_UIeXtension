<h2 align="center">Життєвий цикл <code>UIElement</code> у tModLoader</h2>

Перш ніж переходити до життєвого циклу компоновщиків, слід розглянути життєвий цикл компоновки в **tModLoader**.<br>

1. Для кореневого елемента (`UIState`) викликається метод `Recalculate`.
2. Метод `Recalculate` розраховує 3 області елемента (детальніше про області елемента див. у статті `UIExLayout`).
3. Потім метод `Recalculate` викликає метод `RecalculateChildren`.
4. Метод `RecalculateChildren` викликає `Recalculate` для всіх дочірніх елементів.<br>

Таким чином **tModLoader** викликає метод `Recalculate` для всього дерева елементів кожен кадр.

---

<h2 align="center">Життєвий цикл <code>UIExLayout</code></h2>

Перше, що робить `UIExLayout` — втручається в життєвий цикл `UI` у **tModLoader**:

```csharp
public abstract partial class UIExLayout : UIExElement
{
    private bool _pauseRecalculateChildren = false;

    public override void Recalculate()
    {
        _pauseRecalculateChildren = true;
        base.Recalculate();
        _pauseRecalculateChildren = false;
        RecalculateLayout();
        RecalculateChildren();
    }


    public override void RecalculateChildren()
    {
        if (_pauseRecalculateChildren)
            return;

        base.RecalculateChildren();
    }
}
```

Як видно, `UIExLayout` додає спеціальний прапорець, що блокує виклик `Recalculate` у дочірніх елементів.<br>

Таким чином тепер життєвий цикл виглядає так:

1. Встановлення прапорця `_pauseRecalculateChildren = true`, який забороняє виконання методу `RecalculateChildren`.
2. `base.Recalculate` — перерахунок 3 областей контейнера.
3. `base.Recalculate` викликає `RecalculateChildren`, але виклик цього методу заблокований прапорцем `_pauseRecalculateChildren`.
4. Встановлення прапорця `_pauseRecalculateChildren = false`, який дозволяє виконання методу `RecalculateChildren`.
5. Перерахунок усієї компоновки в методі `RecalculateLayout`.
6. Виклик `RecalculateChildren`.<br>

Тепер:

1. Спочатку перераховуються 3 області контейнера.
2. Елементи всередині контейнера компонуються.
3. Перераховуються 3 області всіх елементів після компоновки.

<h3 align="center">Метод <code>RecalculateLayout</code></h3>

```csharp
protected virtual void RecalculateLayout()
{
    // етап 1:
    var innerDimension = GetInnerDimensions();
    if (innerDimension.Width == 0f && innerDimension.Height == 0f)
        return;

    // етап 2:
    if (IsLayoutPreparation())
        return;

    // етап 3:
    if (_remainingRecalculateLayoutDelayMs > 0)
        return;

    // етап 4:
    UpdateStyleLayoutChildArray();

    // етап 5:
    if (!IsLastLayoutInfoChanged())
        return;

    // етап 6:
    BeginLayoutContext();

    try
    {
        // етап 7:
        PreRefreshLayout();

        // етап 8:
        RefreshLayout();

        // етап 9:
        PostRefreshLayout();

        // етап 10:
        ApplyLayout();

        // етап 11:
        RefreshLayoutDebugLines();
    }
    catch(System.Exception)
    {
        throw new System.Exception("[UIeXtension] RecalculateLayout Exception");
    }
    finally
    {
        // етап 12:
        EndLayoutContext();
    }

    // етап 13:
    UpdateLastLayoutInfo();

    // етап 14:
    int? recalculateLayoutDelayMsState = GetRecalculateLayoutDelayMsState(this);
    _remainingRecalculateLayoutDelayMs =
        recalculateLayoutDelayMsState is not null
            ? (int)recalculateLayoutDelayMsState
            : RecalculateLayoutDelayMs;
}
```

Цей метод визначає весь життєвий цикл компоновки.<br>
Загальні етапи:

1. Перевірка, що контейнер має розмір. Інакше — вихід із методу.
2. Перевірка, що контейнер не перебуває у стані підготовки (див. попередню статтю). Інакше — вихід із методу.
3. Перевірка, що контейнер не має активної затримки перед компоновкою (див. попередню статтю). Інакше — вихід із методу.
4. Оновлення всіх стилів вкладених у контейнер елементів.
5. Перевірка, що інформація після останньої компоновки змінилася (див. попередню статтю). Інакше — вихід із методу.
6. Підготовка тимчасових даних, які використовуються лише під час однієї компоновки.
7. Попередній алгоритм компоновки.
8. Основний алгоритм компоновки.
9. Алгоритм компоновки після основного етапу.
10. Застосування тимчасових даних до елементів (встановлення дочірнім елементам `Width`, `Height`, `Top`, `Left`).
11. Алгоритм розрахунку допоміжних ліній.
12. Звільнення тимчасових даних, які використовуються лише під час компоновки.
13. Запис останніх даних після компоновки (див. попередній розділ).
14. Оновлення мінімальної затримки перед наступною компоновкою.<br>

* Етап 1: проста перевірка.
* Етапи 2-3: розглянуті в попередній статті.
* Етап 4: отримання всіх стилів вкладених елементів та їх збереження в `private Styles.StyleLayoutChild[] _styleLayoutChildArray;`.
* Етап 5: розглянутий у попередній статті.
* Етап 6: розглянутий нижче окремо.
* Етапи 7-9: алгоритми на цих етапах життєвого циклу компоновки визначає кожен компоновщик самостійно.
* Етап 10: розглянутий нижче окремо.
* Етап 11: алгоритм розрахунку допоміжних ліній визначає кожен компоновщик самостійно.
* Етап 12: розглянутий нижче окремо.
* Етап 13: розглянутий у попередній статті.
* Етап 14: див. останні рядки коду вище та попередню статтю.

<h3 align="center">Етапи 6, 12: <code>BeginLayoutContext</code> та <code>EndLayoutContext</code></h3>

У цьому методі готуються/звільняються тимчасові дані, які актуальні лише під час життєвого циклу компоновки.<br>
`UIExLayout` готує дані, які використовуються всіма компоновщиками.<br>
Кожен компоновщик окремо готує/звільняє свої дані.<br><br>

```csharp
protected List<UIElement> _elementsContext = null;

protected List<RectangleLayoutContext> _rectangleContexts = null;

protected List<Styles.StyleLayoutChild> _styleElementsContexts = null;

protected CalculatedStyle _innerDimensionsContext;

protected List<CalculatedStyle> _elementsOuterDimensionsContext = null;

protected List<CalculatedStyle> _elementsDimensionsContext = null;
```

* `_elementsContext` — список дочірніх елементів, які беруть участь у компоновці (у яких поле `StyleLayoutChild().WithoutLayout == false`)
* `_rectangleContexts` — список `RectangleLayoutContext`, якому задаватимуться розмір і зміщення елементів під час компоновки.
* `_styleElementsContexts` — список стилів елементів, які беруть участь у компоновці.
* `_innerDimensionsContext` — внутрішня область компоновщика.
* `_elementsOuterDimensionsContext` — список зовнішніх областей елементів, які беруть участь у компоновці.
* `_elementsDimensionsContext` — список областей елементів, які беруть участь у компоновці.<br>

`_styleElementsContexts`, `_styleElementsContexts`, `_elementsOuterDimensionsContext`, `_elementsDimensionsContext` мають розмір списку, що дорівнює `_elementsContext.Count`.<br>
Усі індекси збігаються.<br><br>

* Усім елементам `_elementsContext` у `BeginLayoutContext` встановлюються значення `Top`, `Left` у `StyleDimension.Empty`.<br>

<!-- -->

* `_rectangleContexts[i].Width` та `_rectangleContexts[i].Height` за замовчуванням мають `_elementsContext[i].Width`, `_elementsContext[i].Height`, розраховані в пікселях.
* `_rectangleContexts[i].Index = i`.<br><br>

`RectangleLayoutContext` має методи:

```csharp
public CalculatedStyle GetCalculatedStyle()
    => new(Left, Top, Width, Height);

public LayoutDebugRectangle GetLayoutDebugRectangle()
    => new(Left, Top, Width, Height);
```

<br>

У методі `EndLayoutContext` усім спискам встановлюється значення `null`.

<h3 align="center">Етап 10: застосування тимчасових даних до елементів</h3>

```csharp
protected virtual void ApplyLayout()
{
    foreach (var rectContext in _rectangleContexts)
        ApplyElementLayout(rectContext);
}

protected virtual void ApplyElementLayout(RectangleLayoutContext rectContext)
{
    UIElement element = _elementsContext[rectContext.Index];

    element.Top.Set(rectContext.Top, 0f);
    element.Left.Set(rectContext.Left, 0f);
    element.Width.Set(rectContext.Width, 0f);
    element.Height.Set(rectContext.Height, 0f);
}
```

На цьому етапі всім елементам, які беруть участь у компоновці, встановлюються значення:

* `Left`;
* `Top`;
* `Width`;
* `Height`.<br>

Усі значення беруться з `_rectangleContexts`.
