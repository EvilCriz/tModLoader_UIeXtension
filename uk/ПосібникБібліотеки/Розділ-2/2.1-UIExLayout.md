3. Організовує зберігання стилів макетування вкладених елементів і доступу до них.
4. Допоміжні статичні методи `Wrap`які будуть описані в цій статті.

- Клавіша 1 - це життєвий цикл макета. Він буде частиною цього розділу, і вам потрібно лише зрозуміти життєвий цикл, якщо ви будете писати посилання на цій бібліотеці.
- Пункт 5, інструменти оптимізації будуть відсортовані в окремій частині санвузла.
- Параграф 3 - буде частково обговорено в цій статті, частково - в окремій частині секції ванної кімнати.

<h2 align="center">Стилі контейнерного розкладу і відстібних елементів</h2>

Клас `UIExLayout` визначає поле:

```csharp
public Styles.StyleLayoutContainer StyleLayout;
```

Цей напрямок містить стилі макетування, які реалізує будь-яке контейнерне планування.<br>

Тип даних `Styles.StyleLayoutContainer` має наступну реалізацію:
```csharp
public class StyleLayoutContainer() : Base.StyleLayoutContainerBase
{
    public UIExOrientation Orientation = UIExOrientation.Vertical;
    public UIExAlignment JustifyContent = UIExAlignment.Auto;
    public UIExAlignment AlignItems = UIExAlignment.Auto;
}
```

- `Orientation` визначає, яка вісь буде вважатися основною для контейнера і яка є поперечною віссю.
- `JustifyContent` і `AlignItems` вказує, як елементи будуть вирівняні вздовж основних і поперечних осей. `UIExAlignment` може приймати такі значення:
  - `Start`: вирівнювання на початку основної / поперечної осі.
  - `Center`: центр вирівнювання базової / поперечної осі.
  - `End`: вирівнювання в кінці основної / поперечної осі.
  - `Stretch`: простягається по осі головного / поперечного руху.
  - `Auto`: дана вартість використовується тільки елементами, які прилягають в контейнері (див. нижче). `JustifyContent` і `AlignItems` рівний `Start`.

----

Клас `Styles.StyleLayoutChild` визначає стилі макета для дитячих елементів контейнера.

```csharp
public class StyleLayoutChild : Base.StyleLayoutChildBase
{
    public UIExAlignment JustifySelf = UIExAlignment.Auto;
    public UIExAlignment AlignSelf = UIExAlignment.Auto;
	
	public UIExThickness Margin = new();

	public bool WithoutLayout = false;

	public StyleDimension Width = default(StyleDimension);
	public StyleDimension Height = default(StyleDimension);
}
```

`JustifySelf` і `AlignSelf` визначає, як елемент буде вирівняти вздовж основної / поперечної осі. `UIExAlignment`Прийняття за зміст. `Auto`І для дитячих елементів контейнера, що значення є запорукою.<br>

Якщо контейнер має значення `JustifyContent == UIExAlignment.Center` - це означає, що всі елементи всередині контейнера будуть відцентровані (центр якого залежить від фіксатора) вздовж основної осі. `JustifySelf == UIExAlignment.Auto`.<br>

`Auto` для в'язаного елемента, це означає, що це займе значення контейнера. `JustifySelf` руді `JustifyContent` для цього конкретного елемента.<br>

для `AlignSelf` Ситуація схожа на поперечну вісь.<br>

Про нас `Margin`, `Width`, `Height` Ми будемо говорити докладніше нижче.<br>

<h2 align="center">Вимкніть елемент з макета</h2>

```csharp
public bool WithoutLayout = false;
```

Це поле відповідає за те, чи ігнорується елемент у макеті.<br>
Всі методи резинизації та позиціонування для такого елемента залишаються стандартними. **tModLoader**
Наприклад, уявіть, що ми створюємо панель для гри саппера. 
- Тут необхідно бути основною панеллю гри (в якій можна додати поле для гри, настройки і т.д.)
- Сама ігрова поле.
- І видалення текстуGAME OVER"право в середині ігрового поля.

<p align="center">
  <img src="../../../Images/LibTutorial/UIExLayout/sapper.png" width="625" height="375">
  <br>
  <em>Рис. 1.1: Схема розміщення (спрощена) гри саппера</em>
</p>

```csharp
// методологія OnActivate(a) в цьому випадку, тільки
// для функції «гарячого перезавантаження коду» у середовищі розробки.
// Щоб скористатися реальним інтерфейсом, краще використовувати реальний інтерфейс.
// методологія OnInitialize()
public override void OnActivate()
{
    RemoveAllChildren();

    // Layout (multiple-stripped) ігри: sapper

    // Панель створюється, що займає 60% екрана і знаходиться в центрі.
    UIPanel panel = new();
    Append(panel);

    // У бібліотеці не визначено метод прикладу.
    SetPrecentSize(panel, left: 0.2f, top: 0.2f, width: 0.6f, height: 0.6f);


    /////////////////////////////////


    // Створено панель. UniformGrid До неї додано 10х10 і гудзики.
    // Сама панель сітки розміщується в панелі і займає ширину: 50%; висота: 80% від розміру панелі.
    UIExUniformGrid grid = new();
    panel.Append(grid);

    SetPrecentSize(grid, left: 0.25f, top: 0.1f, width: 0.5f, height: 0.8f);

    int rows = 10, columns = 10;
    

    /////////////////////////////////


    // Будь ласка, зауважте, що додавання UniformGrid Кнопки повинні бути 100% від розміру комірки.
    grid.StyleLayout.JustifyContent = UIExAlignment.Stretch;
    grid.StyleLayout.AlignItems = UIExAlignment.Stretch;

    for (int row = 0; row < rows; row++)
        for (int column = 0; column < columns; column++)
        {
            UIButton<string> button = new($"[{row},{column}]");
            grid.Append(button);
        }

    // Створює текст. Додана в сітку.
    UIText text = new("GAME OVER");
    text.TextColor = Color.DarkRed;
    StyleLayoutChild styleText = text.StyleLayoutChild();

    // Індексувати, що UniformGrid Ви не повинні керувати текстовим макетом.
    // Це означає, що полотно буде використовуватися. tModLoader
    styleText.WithoutLayout = true;

    // Текст повинен бути в центрі сітки.
    text.HAlign = 0.5f;
    text.VAlign = 0.5f;
    grid.Append(text);
}
```

Якщо ви хочете використовувати тільки цю бібліотеку для облаштування елементів, то ви можете використовувати її для цього завдання. `UIExCanvas`У цьому випадку замінюється частина коду.<br>
Дана частина коду:
```csharp
// Створює текст. Додана в сітку.
UIText text = new("GAME OVER");
text.TextColor = Color.DarkRed;
StyleLayoutChild styleText = text.StyleLayoutChild();

// Індексувати, що UniformGrid Ви не повинні керувати текстовим макетом.
// Це означає, що полотно буде використовуватися. tModLoader
styleText.WithoutLayout = true;

// Текст повинен бути в центрі сітки.
text.HAlign = 0.5f;
text.VAlign = 0.5f;
grid.Append(text);
```

Замінити:
```csharp
UIExCanvas canvas = new();
canvas.Stretch();

UIText text = new("GAME OVER");
text.TextColor = Color.DarkRed;

canvas.StyleLayoutChild().WithoutLayout = true;

canvas.StyleLayout.JustifyContent = UIExAlignment.Center;
canvas.StyleLayout.AlignItems = UIExAlignment.Center;

canvas.Append(text);
grid.Append(canvas);
```

<h2 align="center">Посада і розмір в'язаних елементів</h2>

Про позиції, які необхідно знати:
- Компоненти ніколи не дивляться на значення. `Left`, `Top` клас `UIElement`.
- Компоненти встановлюють ці значення, ігноруючи значення, встановлених до макета.<br>
<!-- -->
- Тільки один лансер дозволяє встановлювати абсолютні координати елемента: `UIExCanvas`.
- `UIExCanvas` Дозвілля **4** абсолютні координати за допомогою спеціального класу стилів відстібних елементів.
- Всі інші конструктори використовують абсолютно різні системи.<br>
<!-- -->
Для підведення підсумків:
- Напильники `Left` і `Top` елементи, вбудовані в макет, не впливають на макет, і після планування, швидше за все, будуть відрізнятися від своїх значень до неї.<br>

----

Про розмір, який потрібно знати:
- Компоненти ніколи не дивляться на значення. `Width`, `Height` клас `UIElement`.
- Компоненти встановлюють ці значення, ігноруючи значення, встановлених до макета.<br>
<!-- -->
- Початкові розміри визначаються `Width` і `Height` клас `StyleLayoutChild`.
- Ці значення у класі стилю використовуються тільки за посиланнями. Зовні зв'язки, вони не роблять нічого.
- `MinWidth`, `MaxWidth`, `MinHeight` і `MaxHeight` В якості нормального використання класу немає даних полів. `StyleLayoutChild`, і їх значення приймають з `UIElement`.<br>
<!-- -->
Чому б будівельник потребує окремих однакових полів?
- Частина вкладників одночасно змінює розміри і зібрання на основі оригінальних розмірів елементів.
- Таким чином, посилання може змінити розмір, встановити поля. `Width` і `Height` специфічний `UIElement` І в наступний раз, ви вставите його разом, оригінальні розміри будуть втрачені.
- Таким чином, макет дасть абсолютно різні результати з кожною ітерацією.
- Для усунення цієї проблеми були введені окремі поля розмірів.

<h2 align="center"><code>Margin</code>, <code>Padding</code>, <code>Stretch</code> 3 зони елемента</h2>

У розділі передбачено детальний опис моделі макета бібліотеки.
Ця інформація особливо важлива в 3-х випадках:
1. Ви плануєте малювати власні елементи на екрані (то просто зробити це самостійно). `Left`, `Top`, `Width`, `Height` Не працює.
2. Ви плануєте написати свій власний композитор на основі цієї бібліотеки.
3. Ви хотіли б зрозуміти, як загальний принцип лайнера позбавляє від елементів (розпилювачі) `Margin`, `Padding`, `Stretch`, його площа і ділянки елементів.

Кожен елемент має 3 регіони (головки з прямим кутом + розмір):
1. Площа самого елемента.
2. Зовнішня область елемента.
3. Внутрішній регіон елемента.<br>

Будь-які контейнери в роботі макета **Чистий** з зовнішнім регіоном елемента.<br>
Це головне, що потрібно знати при роботі з конструктором цієї бібліотеки або створення власної бібліотеки.<br>
Контейнер не піклується про нормальну або внутрішню площу елемента.<br>
У контейнері є тільки важливі:
1. Власна внутрішня область.
2. Зовнішня область дитячих елементів.

**Площа самого елемента** - Непросто. `Left`, `Top`, `Width`, `Height`.<br>
`Left` і `Top` Це зміщення елемента відносно внутрішнього регіону батьківського елемента. 
Після рекалькуляції `UIElement` зберігає площу елемента:
1. `X-области`: `X` внутрішня зона батьків (у абсолютній координаті від початку екрана) `Left-элемента`.
2. `Y-области`: `Y` внутрішня зона батьків (у абсолютній координаті від початку екрана) `Top-элемента`.
3. `ActualWidth-области`: `Clamp(Width, MinWidth, MaxWidth)`.
4. `ActualHeight-области`: `Clamp(Height, MinHeight, MaxHeight)`.<br>

Площа елемента – це абсолютні координати. **X/Y** від початку екрана + розмір елемента, обмежений `Min` і `Max`.

----

**Область самого елемента (паграф 1)** Визначено (для будівельників цієї бібліотеки) за наступним алгоритмом:
1. Прийнято розмір зони вільного простору (підписаний за посиланнями) для розміщення.
2. На основі розміру площі виділеного простору та значень (`Width`, `MinWidth`, `MaxWidth`, `Height`, `MinHeight`, `MaxHeight`) розмір елемента визначається.
3. На основі зміщення площі виділеного простору та значень `Top` і `Left` Визначено поточне положення пункту (відносно до початку екрана, а не батьківського елемента).
Наприклад:
```csharp
// методологія OnActivate(a) в цьому випадку, тільки
// для функції «гарячого перезавантаження коду» у середовищі розробки.
// Щоб скористатися реальним інтерфейсом, краще використовувати реальний інтерфейс.
// методологія OnInitialize()
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Left.Precent = 0.1f;
    canvas.Top.Precent = 0.1f;
    canvas.Width.Precent = 0.8f;
    canvas.Height.Precent = 0.8f;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();
    StyleLayoutChildCanvas innerPanelStyleCanvas = innerPanelStyle.Canvas();

    innerPanel.MaxWidth.Set(50f, 0f);
    innerPanelStyle.Width.Pixels = 100f;
    innerPanelStyle.Height.Precent = 0.5f;

    innerPanelStyleCanvas.Left.Pixels = 50f;
    innerPanelStyleCanvas.Top.Pixels = 50f;

    canvas.Append(innerPanel);
    Append(canvas);
}
```
1. `canvas` Починається на 10 відсотків висоти/ширині екрана, і це 80 відсотків висоти/ширині екрана, і це площа полотна.
2. `innerPanel` Він має ширину 100 пікселів і максимальну ширину 50 пікселів. Ширина області становитиме 50 пікселів.
3. `innerPanel` Має висоту 50% висоти батьківського елемента.
4. `innerPanel` зміщення 50 пікселів над `Left` Про батьківський елемент. `X-области` буде: 10% ширини екрану + 50 пікселів.
5. `innerPanel` зміщення 50 пікселів над `Top` Про батьківський елемент. `Y-области` Це буде 10% від висоти екрану + 50 пікселів.<br>

Давайте скажемо наш екран за розмірами. `1000x500`Далі:<br>
Домен `canvas`:
1. `X`: 1000 * 0.1 = 100px;
2. `Y`: 500 * 0.1 = 50px;
3. `Width`: 1000 * 0.8 = 800px;
4. `Height`: 500 * 0.8 = 400px;<br>

А потім поле `innerPanel` Розраховується наступним чином:
1. `X`: `область-canvas-x` + `innerPanelStyleCanvas.Left` >>> `100px + 50px`.
2. `Y`: `область-canvas-y` + `innerPanelStyleCanvas.Top` >>> `50px + 50px`.
3. `Width` `Width = 100px`, `MaxWidth = 50px` >>> 50px;
4. `Height`: `область-canvas-Height * 0.5 = 400px * 0.5`.<br>

Результат:
1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.

**Зовнішній регіон** Це елемент. **КОМПЛЕКС** + Маргін (але з нюансами описано нижче).<br>

Змінення коду раніше:
```csharp
// методологія OnActivate(a) в цьому випадку, тільки
// для функції «гарячого перезавантаження коду» у середовищі розробки.
// Щоб скористатися реальним інтерфейсом, краще використовувати реальний інтерфейс.
// методологія OnInitialize()
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Left.Precent = 0.1f;
    canvas.Top.Precent = 0.1f;
    canvas.Width.Precent = 0.8f;
    canvas.Height.Precent = 0.8f;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();
    StyleLayoutChildCanvas innerPanelStyleCanvas = innerPanelStyle.Canvas();

    innerPanel.MaxWidth.Set(50f, 0f);
    innerPanelStyle.Width.Pixels = 100f;
    innerPanelStyle.Height.Precent = 0.5f;

    innerPanelStyleCanvas.Left.Pixels = 50f;
    innerPanelStyleCanvas.Top.Pixels = 50f;

    innerPanelStyle.Margin = new(
        pixels: true,
        left:   25f,
        top:    50f,
        right:  75f,
        bottom: 100f);

    canvas.Append(innerPanel);
    Append(canvas);
}
```
Домен `innerPanel`:
1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.<br>

Зовнішня територія вважається наступним чином:
1. `outer-X`: `X - Margin.Left`.
2. `outer-Y`: `Y - Margin.Top`.
3. `outer-Width`: `Width + Margin.Left + Margin.Right`.
4. `outer-Height`: `Height + Margin.Top + Margin.Bottom`.<br>

Зовнішній регіон `innerPanel`
1. `outer-X`: `150px - 25px = 125px`.
2. `outer-Y`: `100px - 50px = 50px`.
3. `outer-Width`: `50px + 25px + 75px = 150px`.
4. `outer-Height`: `200px + 50px + 100px = 350px`.<br>

І ось важливо: Розмір елемента, який ви бачите на екрані, завжди розмір площі (не зовні або всередині).<br>
Розмір зовнішньої зони тільки впливає на скільки простору, пов'язавшись з тим, що елемент займає.<br>
У цьому випадку елемент буде візуально зайнятий `50x200px`Але для фіксаторів (наприклад, `UIExGrid`) - елемент буде зайнятий `150x350px`.<br>
Якщо цей елемент знаходиться в `UIExGrid` в комірці, яка повинна самостійно регулювати розмір елемента в ньому - вона буде регулюватися до розміру `150x350px`Це, клітина буде більшою, ніж видимий розмір елемента.

Малий підсумок `Marign`:
1. `Margin.Top` і `Margin.Left`: збільшити зовнішній регіон і створити простір між правою/лівою межею зовнішньої області і зоною елемента.
2. `Margin.Right` і `Margin.Bottom`: збільшити зовнішній регіон і створити простір між правою/низьковою межею зовнішньої області і зоною елемента.<br>
Так, `Margin` Не змінює розмір самого елемента, він змінює простір, який заповнює посилання на цю область.

**Внутрішній район елемента** Це область, де, згідно з «опіоном» даного елемента, елементи, вбудовані в нього, повинні бути розміщені.<br>
За замовчуванням. **КОМПЛЕКС** і **пердят** той же.<br>
Внутрішній район визначається за допомогою `PaddingLeft`, `PaddingTop`, `PaddingRight`, `PaddingBottom`.<br>
У цій бібліотеці немає аналогів цих полів. `UIElement`Ці значення повинні бути використані безпосередньо з будь-якого `UIElement`.<br>

Бібліотека використовує власну бібліотеку `Padding` в окремих контейнерах макета, але він ніколи не вказаний безпосередньо `UIElement`.<br>

Для полегшення створення `UIElement-оберток` клас `UIExLayout` забезпечує статичні методи `Wrap`:

```csharp
public static TUIElement Wrap<TUIElement>(UIElement element, bool stretch = false, bool center = false)
    where TUIElement : UIElement, new()
        => Wrap(element, new TUIElement(), stretch, center);

public static TUIElement Wrap<TUIElement>(UIElement element, TUIElement wrapElement, bool stretch = false, bool center = false)
    where TUIElement : UIElement
{
    if (stretch)
    {
        element.Width.Set(0f, 1f);
        element.Height.Set(0f, 1f);
    }

    if (center)
    {
        element.HAlign = 0.5f;
        element.VAlign = 0.5f;
    }

    wrapElement.Append(element);
    return wrapElement;
}
```

Сам метод створює обгортку для даного елемента і повертає його.<br>
Тепер замініть попередній код за допомогою методу обгортання.

```csharp
// "UIPanel Панель2 = новий();" від ручного коду, заміну:
UIPanel panel2 = new();
panel2.MarginTop = 10f;

var wrapElement = UIExLayout.Wrap<UIElement>(panel2, stretch: true, center: false);



// "stackPanel.Append(panel2);" з пеультим кодом буде замінено:
stackPanel.Append(wrapElement);
```

Що робить цей код:
1. Референти до статичного методу `Wrap` класUIExLayout'.
2. Передається як універсальний тип. `UIElement`Це тип інтерфейсу користувача, який наш елемент буде загорнути.
3. Перший аргумент:`panel2`- Наші `UIElement` Або загорнути спадкоємцем.
4. Другий аргумент:`stretch: true`) - прапор, що вказує на те, що необхідно розтягувати об'єкт, загорнути по всій площі обгортки. `true` - для `panel2` Цінності будуть встановлені: `Width.Set(0f, 1f)`, `Height.Set(0f, 1f)`.
5. Третій аргумент:`center: false`) - прапор, що вказує на те, що необхідно розмістити об'єкт, який буде загорнути в центрі зони обгортання. `true` - для `panel2` визначати значення `HAlign = 0.5f; VAlign = 0.5f`.

```csharp

canvas.Stretch();

///////////////////////

UIExStackPanel stackPanel = new();
canvas.Append(stackPanel);

stackPanel.Stretch();

```

1. `canvas` і `stackPanel` методологія `Stretch()`.
2. `canvas` вставка `UIState`який використовує стандарт для **tModLoader** Методи розміщення / розміри.
   - Відповідно, метод `Stretch` Він чудово працює.
3. `stackPanel` вставка `canvas`які **Нема.** Використання стандартних значень `Top`, `Left`, `Width`, `Height`.
   - Відповідно, метод `Stretch` нема нічого для `stackPanel`.

<h2 align="center">Дисплей допоміжних ліній</h2>

Клас `UIExLayout` додає поля:

```csharp
public bool ShowLayoutLines = false;
public float LayoutLinesThickness = 1f;
public Color LayoutLinesColor = Color.LightGray;
```

- `ShowLayoutLines` - вказує на те, що після планування необхідно відображати допоміжні лінії зверху елемента.
- `LayoutLinesThickness` - розмір допоміжних ліній, що не використовуються, якщо `ShowLayoutLines == false`.
- `LayoutLinesColor` - колір допоміжних ліній, що не використовуються, якщо `ShowLayoutLines == false`.
<br>

І хоча ці поля використовують всі контейнери макета, принцип, на які вони будуть намальовані, будуть відрізнятися від одного контейнера до іншого.<br>
```csharp
UIExStackPanel stackPanel = new();
UIExGrid grid = new();
stackPanel.ShowLayoutLines = true; // Лінії будуть відображатися як прямокутник () навколо виділеного простору для кожного елемента.
grid.ShowLayoutLines = true; // Лінії будуть відображатися в якості сітки.
```


`UIExLayout` Методи реалізації:
```csharp
public void SetLayoutLinesInfoForBranch(bool state, float? thickness = null, Color? color = null) { /* ... */ }
public void SetLayoutLinesInfoForTree(bool state, float? thickness = null, Color? color = null) { /* ... */ }
```

- `SetLayoutLinesInfoForBranch` Призначає передачу (не) null) значення для поточного елемента і всіх його нащадків, які успадкують клас `UIExLayout`
- `SetLayoutLinesInfoForTree` Виглядає за кореневим елементом батьків і викликає метод для нього. `SetLayoutLinesInfoForBranch`


<br>Лінії. **Нема.** добірка UIВони намальовані прямо над верхом. `UIExLayout`.<br>

3. Вивчення частини даного розділу, присвяченого оптимізації елементів макета.
4. Обстеження всіх інших елементів макета.
5. Обстеження решти статей цього розділу.
- І знову, найголовніше про елементи макета, не запускається використання елементів макета в реальних проектах, доки ви вивчили статтю оптимізації. Різниця продуктивності буде дуже значним.
