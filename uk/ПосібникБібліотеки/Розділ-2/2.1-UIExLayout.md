<h1 align="center">Клас <code>UIExLayout</code>. Основи компонування</h1>

---

* Ця бібліотека передбачає, що ви вже вивчили [базовий посібник tModLoader з користувацького інтерфейсу](https://github.com/tModLoader/tModLoader/wiki/Basic-UI-Element)<br>
* Ця бібліотека передбачає, що ви вже вивчили [розширений посібник з налаштування користувацького інтерфейсу](https://github.com/tModLoader/tModLoader/wiki/Advanced-guide-to-custom-UI)<br>
* Ця стаття передбачає, що ви вивчили статтю: [«структура стилів»](../Розділ-1/1.3-StyleStructure.md)

---

<br>

Клас `UIExLayout` є базовим класом для елементів компонування. Він реалізує:

1. Життєвий цикл компонування елементів.
2. Стилі компонування контейнера, які підтримує будь-який елемент компонування.
3. Організовує зберігання стилів компонування вкладених елементів і доступ до них.
4. Допоміжні статичні методи `Wrap`, які будуть описані в цій статті.
5. Інструменти оптимізації, частина яких передається під зовнішнє керування (через внутрішні обмеження **tModLoader**).

   <br>

* У цій статті будуть розглянуті ці пункти, крім:
* Пункту 1 — життєвого циклу компонування. Буде розглянуто в окремій частині цього розділу. Вам потрібно розуміти життєвий цикл, тільки якщо ви плануєте писати власний компоновщик на основі цієї бібліотеки.
* Пункту 5 — інструментів оптимізації. Будуть розглядатися в окремій частині цього розділу.
* Пункту 3 — частково буде розглянуто в цій статті, частково — в окремій частині цього розділу.

<h2 align="center">Стилі компонування контейнера та вкладених елементів</h2>

Клас `UIExLayout` визначає поле:

```csharp
public Styles.StyleLayoutContainer StyleLayout;
```

Це поле містить стилі компонування, які реалізує будь-який контейнер компонування.<br>

Тип даних `Styles.StyleLayoutContainer` має таку реалізацію:

```csharp
public class StyleLayoutContainer() : Base.StyleLayoutContainerBase
{
    public UIExOrientation Orientation = UIExOrientation.Vertical;
    public UIExAlignment JustifyContent = UIExAlignment.Auto;
    public UIExAlignment AlignItems = UIExAlignment.Auto;
}
```

* `Orientation` визначає, яка вісь вважатиметься головною для контейнера, а яка — поперечною.
* `JustifyContent` і `AlignItems` вказують, як будуть вирівнюватися елементи за головною та поперечною осями. `UIExAlignment` може приймати такі значення:

  * `Start`: вирівнювання за початком головної / поперечної осі.
  * `Center`: вирівнювання по центру головної / поперечної осі.
  * `End`: вирівнювання за кінцем головної / поперечної осі.
  * `Stretch`: розтягує за головною / поперечною віссю.
  * `Auto`: це значення використовують тільки вкладені в контейнер елементи (див. нижче). Використання цього значення для `JustifyContent` і `AlignItems` буде прирівняне до значення `Start`.

---

Клас `Styles.StyleLayoutChild` визначає стилі компонування для дочірніх елементів контейнера.

```csharp
public class StyleLayoutChild : Base.StyleLayoutChildBase
{
    public UIExAlignment JustifySelf = UIExAlignment.Auto;
    public UIExAlignment AlignSelf = UIExAlignment.Auto;
	
	public UIExThickness Margin = new();

	public bool WithoutLayout = false;

	public StyleDimension Width = default(StyleDimension);
	public StyleDimension Height = default(StyleDimension);
}
```

`JustifySelf` і `AlignSelf` визначають, як елемент буде вирівнюватися за головною / поперечною віссю. Вище ми вже розбирали значення `UIExAlignment`. Крім значення `Auto`. І для дочірніх елементів контейнера це значення є ключовим.<br>

Якщо у контейнера значення `JustifyContent == UIExAlignment.Center` — це означає, що всі елементи всередині контейнера будуть розташовані по центру (центру чого саме — залежить від компоновщика) за головною віссю. І це правило працює для всіх дочірніх елементів, у яких значення `JustifySelf == UIExAlignment.Auto`.<br>

`Auto` для вкладеного елемента означає, що він візьме значення контейнера. Будь-яке інше значення `JustifySelf` перевизначить `JustifyContent` для цього конкретного елемента.<br>

Для `AlignSelf` ситуація аналогічна для поперечної осі.<br>

Про `Margin`, `Width`, `Height` ми докладніше поговоримо нижче.<br>

<h2 align="center">Вимкнення елемента з компонування</h2>

```csharp
public bool WithoutLayout = false;
```

Це поле відповідає за те, чи буде елемент ігноруватися під час компонування.<br>
Усі способи зміни розміру та розташування для такого елемента залишаються стандартними для **tModLoader**.
Наприклад: уявімо, що ми створюємо панель для гри в сапера.

* Має бути основна панель гри (у яку можна буде додати ігрове поле, налаштування тощо).
* Саме ігрове поле.
* І виведення тексту "GAME OVER" прямо по центру ігрового поля.

<p align="center">
  <img src="../../../Images/LibTutorial/UIExLayout/sapper.png" width="625" height="375">
  <br>
  <em>Рис. 1.1. Макет (спрощений) гри «сапер»</em>
</p>

```csharp
// метод OnActivate() у цьому випадку використовується лише
// для функції «гарячого перезавантаження коду» в середовищі розробки.
// для реального інтерфейсу правильніше було б використовувати
// метод OnInitialize()
public override void OnActivate()
{
    RemoveAllChildren();

    // Макет (у багато разів скорочений) гри: Сапер

    // Створюється панель, що займає 60% екрана та розташовується по центру.
    UIPanel panel = new();
    Append(panel);

    // написаний для прикладу метод. НЕ визначений у самій бібліотеці.
    SetPrecentSize(panel, left: 0.2f, top: 0.2f, width: 0.6f, height: 0.6f);


    /////////////////////////////////


    // Створюється панель UniformGrid 10х10 і в неї додаються кнопки.
    // Сама Grid панель поміщається в panel і займає width: 50%; height: 80% від розмірів panel.
    UIExUniformGrid grid = new();
    panel.Append(grid);

    SetPrecentSize(grid, left: 0.25f, top: 0.1f, width: 0.5f, height: 0.8f);

    int rows = 10, columns = 10;
    

    /////////////////////////////////


    // Вказуємо, що додані в UniformGrid кнопки повинні займати 100% розміру комірки.
    grid.StyleLayout.JustifyContent = UIExAlignment.Stretch;
    grid.StyleLayout.AlignItems = UIExAlignment.Stretch;

    for (int row = 0; row < rows; row++)
        for (int column = 0; column < columns; column++)
        {
            UIButton<string> button = new($"[{row},{column}]");
            grid.Append(button);
        }

    // Створює текст. Він додається в grid.
    UIText text = new("GAME OVER");
    text.TextColor = Color.DarkRed;
    StyleLayoutChild styleText = text.StyleLayoutChild();

    // Вказуємо, що UniformGrid не повинен керувати компонуванням text
    // Це означає, що використовуватися буде Canvas tModLoader
    styleText.WithoutLayout = true;

    // Вказуємо, що текст має бути точно по центру grid.
    text.HAlign = 0.5f;
    text.VAlign = 0.5f;
    grid.Append(text);
}
```

Якщо ви хочете для розташування елементів використовувати тільки цю бібліотеку, то для цього завдання можна було б використати `UIExCanvas`. У цьому випадку частина коду замінюється.<br>
Ця частина коду:

```csharp
// Створює текст. Він додається в grid.
UIText text = new("GAME OVER");
text.TextColor = Color.DarkRed;
StyleLayoutChild styleText = text.StyleLayoutChild();

// Вказуємо, що UniformGrid не повинен керувати компонуванням text
// Це означає, що використовуватися буде Canvas tModLoader
styleText.WithoutLayout = true;

// Вказуємо, що текст має бути точно по центру grid.
text.HAlign = 0.5f;
text.VAlign = 0.5f;
grid.Append(text);
```

Замінюється на:

```csharp
UIExCanvas canvas = new();
canvas.Stretch();

UIText text = new("GAME OVER");
text.TextColor = Color.DarkRed;

canvas.StyleLayoutChild().WithoutLayout = true;

canvas.StyleLayout.JustifyContent = UIExAlignment.Center;
canvas.StyleLayout.AlignItems = UIExAlignment.Center;

canvas.Append(text);
grid.Append(canvas);
```

<h2 align="center">Позиція та розміри вкладених елементів</h2>

Про позиції вам потрібно знати наступне:

* Компоновщики ніколи не дивляться на значення `Left`, `Top` класу `UIElement`.
* Компоновщики встановлюють ці значення, ігноруючи їхні значення, встановлені до компонування.<br>

<!-- -->

* Тільки один компоновщик дозволяє задавати абсолютні координати елемента: `UIExCanvas`.
* `UIExCanvas` дозволяє задавати **4** абсолютні координати за допомогою спеціального класу стилів вкладених елементів.
* Усі інші компоновщики використовують зовсім інші системи.<br>

<!-- -->

Підсумовуючи:

* Значення `Left` і `Top` елементів, вкладених у компоновщик, не впливають на компонування, і після компонування, найімовірніше, відрізнятимуться від своїх значень до нього.<br>

---

Про розміри вам потрібно знати наступне:

* Компоновщики ніколи не дивляться на значення `Width`, `Height` класу `UIElement`.
* Компоновщики встановлюють ці значення, ігноруючи їхні значення, встановлені до компонування.<br>

<!-- -->

* Початкові розміри встановлюються за допомогою `Width` і `Height` класу `StyleLayoutChild`.
* Ці значення розмірів із класу стилів використовують тільки компоновщики. Поза компоновщиками вони нічого не роблять.
* `MinWidth`, `MaxWidth`, `MinHeight` і `MaxHeight` використовуються у звичайному режимі. Цих полів немає в класі `StyleLayoutChild`, і їхні значення беруться з `UIElement`.<br>

<!-- -->

Навіщо компоновщику окремі ідентичні поля?

* Частина компоновщиків одночасно змінює розміри та компонує, виходячи з початкових розмірів елементів.
* Таким чином, компоновщик може змінити розмір, встановити поля `Width` і `Height`, визначені в `UIElement`, і під час наступного компонування початкові розміри будуть втрачені.
* Таким чином, компонування даватиме зовсім різні результати з кожною своєю ітерацією.
* Для виключення цієї проблеми й були введені окремі поля розмірів.

<h2 align="center"><code>Margin</code>, <code>Padding</code>, <code>Stretch</code> і 3 області елемента</h2>

Цей розділ містить докладний опис моделі компонування бібліотеки.
Ця інформація особливо важлива у 3 випадках:

1. Ви плануєте самостійно малювати елементи на екрані (тоді просто використовувати `Left`, `Top`, `Width`, `Height` не вийде).
2. Ви плануєте писати власний компоновщик на основі цієї бібліотеки.
3. Ви хотіли б зрозуміти, за яким загальним принципом компоновщик розташовує елементи (враховуючи `Margin`, `Padding`, `Stretch`, свою область та області елементів).

Кожен елемент має 3 області (координати верхнього-лівого кута + розмір):

1. Область самого елемента.
2. Зовнішня область елемента.
3. Внутрішня область елемента.<br>

Будь-які контейнери компонування працюють **ВИКЛЮЧНО** із зовнішньою областю елемента.<br>
Це головне, що ви повинні знати під час роботи з компоновщиком цієї бібліотеки або створення власних.<br>
Контейнеру не важлива звичайна або внутрішня область елемента.<br>
Контейнеру важливі лише:

1. Його власна внутрішня область.
2. Зовнішня область дочірніх елементів.

**Область самого елемента** — це не просто `Left`, `Top`, `Width`, `Height`.<br>
`Left` і `Top` — це зміщення елемента відносно внутрішньої області батьківського елемента.
Після перерахунку `UIElement` зберігає область елемента так:

1. `X-області`: `X` внутрішньої області батьківського елемента (в абсолютній координаті від початку екрана) + `Left-елемента`.
2. `Y-області`: `Y` внутрішньої області батьківського елемента (в абсолютній координаті від початку екрана) + `Top-елемента`.
3. `ActualWidth-області`: `Clamp(Width, MinWidth, MaxWidth)`.
4. `ActualHeight-області`: `Clamp(Height, MinHeight, MaxHeight)`.<br>

Тобто область елемента — це його абсолютні координати **X/Y** від початку екрана + розмір елемента, обмежений `Min` і `Max`.

---

**Область самого елемента (пункт 1)** визначається (у компоновщиків цієї бібліотеки) за таким алгоритмом:

1. Береться розмір області вільного простору (виділений компоновщиком) для розміщення.
2. Виходячи з розміру області виділеного простору та значень (`Width`, `MinWidth`, `MaxWidth`, `Height`, `MinHeight`, `MaxHeight`) визначається розмір елемента.
3. Виходячи зі зміщення області виділеного простору та значень `Top` і `Left` визначається поточне положення елемента (відносно початку екрана, а не батьківського елемента).
   Наприклад:

```csharp
// метод OnActivate() у цьому випадку використовується лише
// для функції «гарячого перезавантаження коду» в середовищі розробки.
// для реального інтерфейсу правильніше було б використовувати
// метод OnInitialize()
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Left.Precent = 0.1f;
    canvas.Top.Precent = 0.1f;
    canvas.Width.Precent = 0.8f;
    canvas.Height.Precent = 0.8f;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();
    StyleLayoutChildCanvas innerPanelStyleCanvas = innerPanelStyle.Canvas();

    innerPanel.MaxWidth.Set(50f, 0f);
    innerPanelStyle.Width.Pixels = 100f;
    innerPanelStyle.Height.Precent = 0.5f;

    innerPanelStyleCanvas.Left.Pixels = 50f;
    innerPanelStyleCanvas.Top.Pixels = 50f;

    canvas.Append(innerPanel);
    Append(canvas);
}
```

1. `canvas` починається з 10% від висоти/ширини екрана і має розмір у 80% висоти/ширини екрана. Це і є область canvas.
2. `innerPanel` має ширину: 100 пікселів і максимальну ширину 50 пікселів. Ширина області буде — 50 пікселів.
3. `innerPanel` має висоту: 50% від висоти батьківського елемента.
4. `innerPanel` зміщена на 50 пікселів за `Left` відносно батьківського елемента. Отже `X-області` буде: 10% від ширини екрана + 50 пікселів.
5. `innerPanel` зміщена на 50 пікселів за `Top` відносно батьківського елемента. Отже `Y-області` буде: 10% від висоти екрана + 50 пікселів.<br>

Уявімо, що наш екран має розмір `1000x500`, тоді:<br>
Область `canvas`:

1. `X`: 1000 * 0.1 = 100px;
2. `Y`: 500 * 0.1 = 50px;
3. `Width`: 1000 * 0.8 = 800px;
4. `Height`: 500 * 0.8 = 400px;<br>

І тоді область `innerPanel` обчислюється так:

1. `X`: `область-canvas-x` + `innerPanelStyleCanvas.Left` >>> `100px + 50px`.
2. `Y`: `область-canvas-y` + `innerPanelStyleCanvas.Top` >>> `50px + 50px`.
3. `Width` `Width = 100px`, `MaxWidth = 50px` >>> 50px;
4. `Height`: `область-canvas-Height * 0.5 = 400px * 0.5`.<br>

Результат:

1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.

**Зовнішня область** елемента. Це **область елемента** + Margin (але з нюансами, про які написано нижче).<br>

Модифікуємо код раніше:

```csharp
// метод OnActivate() у цьому випадку використовується лише
// для функції «гарячого перезавантаження коду» в середовищі розробки.
// для реального інтерфейсу правильніше було б використовувати
// метод OnInitialize()
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Left.Precent = 0.1f;
    canvas.Top.Precent = 0.1f;
    canvas.Width.Precent = 0.8f;
    canvas.Height.Precent = 0.8f;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();
    StyleLayoutChildCanvas innerPanelStyleCanvas = innerPanelStyle.Canvas();

    innerPanel.MaxWidth.Set(50f, 0f);
    innerPanelStyle.Width.Pixels = 100f;
    innerPanelStyle.Height.Precent = 0.5f;

    innerPanelStyleCanvas.Left.Pixels = 50f;
    innerPanelStyleCanvas.Top.Pixels = 50f;

    innerPanelStyle.Margin = new(
        pixels: true,
        left:   25f,
        top:    50f,
        right:  75f,
        bottom: 100f);

    canvas.Append(innerPanel);
    Append(canvas);
}
```

Область `innerPanel`:

1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.<br>

А зовнішня область обчислюється наступним чином:

1. `outer-X`: `X - Margin.Left`.
2. `outer-Y`: `Y - Margin.Top`.
3. `outer-Width`: `Width + Margin.Left + Margin.Right`.
4. `outer-Height`: `Height + Margin.Top + Margin.Bottom`.<br>

Зовнішня область `innerPanel`

1. `outer-X`: `150px - 25px = 125px`.
2. `outer-Y`: `100px - 50px = 50px`.
3. `outer-Width`: `50px + 25px + 75px = 150px`.
4. `outer-Height`: `200px + 50px + 100px = 350px`.<br>

І тут важливий момент. Розмір самого елемента, який ви бачите на екрані, — це завжди розмір області (не зовнішньої або внутрішньої).<br>
Розмір зовнішньої області впливає тільки на те, скільки, на думку компоновщика, простору займає елемент.<br>
У цьому випадку — елемент візуально буде займати `50x200px`. Але для компоновщиків (наприклад `UIExGrid`) — елемент буде займати `150x350px`.<br>
Якщо цей елемент буде знаходитися в `UIExGrid` у комірці, яка має сама підлаштовуватися під розмір елемента в ній — вона буде підлаштовуватися під розмір `150x350px`, тобто комірка буде більшою за видимий розмір елемента.

Невеликий підсумок щодо `Marign`:

1. `Margin.Top` і `Margin.Left`: збільшують зовнішню область і створюють простір між верхньою/лівою межею зовнішньої області та областю елемента.
2. `Margin.Right` і `Margin.Bottom`: збільшують зовнішню область і створюють простір між правою/нижньою межею зовнішньої області та областю елемента.<br>
   Таким чином, `Margin` не змінює розмір області самого елемента — він змінює простір, який компоновщик резервує навколо цієї області

**Внутрішня область елемента** — це область, де, на «думку» цього елемента, мають розташовуватися вкладені в нього елементи.<br>
За замовчуванням **область елемента** та **внутрішня область** однакові.<br>
Внутрішня область задається за допомогою `PaddingLeft`, `PaddingTop`, `PaddingRight`, `PaddingBottom`.<br>
Аналогів цих полів у цій бібліотеці (для `UIElement`) немає. Ці значення коректно використовувати безпосередньо в будь-якому `UIElement`.<br>

У бібліотеці використовується власний `Padding` в окремих контейнерах компонування, але він ніколи не задається безпосередньо `UIElement`.<br>

Крім цього, `PaddingLeft`, `PaddingTop`, `PaddingRight`, `PaddingBottom` можуть автоматично керуватися класом `UIExElement`.<br>
Дивіться докладнішу інформацію в розділі 3: «Клас `UIExElement`».<br><br>

Область `innerPanel`:

1. `X`: `150px`.
2. `Y`: `100px`.
3. `Width`: `50px`.
4. `Height`: `200px`.<br>

Внутрішня область обчислюється наступним чином:

1. `inner-X`: `X + PaddingLeft`.
2. `inner-Y`: `Y + PaddingTop`.
3. `inner-Width`: `Width - PaddingLeft - PaddingRight`.
4. `inner-Height`: `Height - PaddingTop - PaddingBottom`.<br>

Припустимо:

```csharp
innerPanel.PaddingLeft = 10f;
innerPanel.PaddingTop = 20f;
innerPanel.PaddingRight = 30f;
innerPanel.PaddingBottom = 40f;
```

Тоді внутрішня область `innerPanel`:

1. `inner-X`: `150px + 10px = 160px`.
2. `inner-Y`: `100px + 20px = 120px`.
3. `inner-Width`: `50px - 10px - 30px = 10px`.
4. `inner-Height`: `200px - 20px - 40px = 140px`.<br>

// для реального інтерфейсу правильніше було б використовувати

    canvas.Height.Precent = 1f;

    canvas.PaddingLeft = 20f;
    canvas.PaddingTop = 40f;

2. `inner-Y`: `Y == 0` + `PaddingTop == 40px`.
3. `inner-Width`: `Width == screeWidth` - `PaddingLeft == 20px` - `PaddingRight == 60px`.

І тепер найважливіше. Елемент компонування розташовує **ЗОВНІШНЮ** область елементів.

```csharp
// метод OnActivate() у цьому випадку використовується лише
// для функції «гарячого перезавантаження коду» в середовищі розробки.
// для реального інтерфейсу правильніше було б використовувати
// метод OnInitialize()
public override void OnActivate()
{
    RemoveAllChildren();

    UIExCanvas canvas = new();
    canvas.Width.Precent = 1f;
    canvas.Height.Precent = 1f;
    canvas.StyleLayout.JustifyContent = UIExAlignment.Center;
    canvas.StyleLayout.AlignItems = UIExAlignment.Center;

    UIPanel innerPanel = new();

    StyleLayoutChild innerPanelStyle = innerPanel.StyleLayoutChild();

    innerPanelStyle.Width.Pixels = 50f;
    innerPanelStyle.Height.Pixels = 50f;

    innerPanelStyle.Margin = new(
        pixels: true,
        top:    10f,
        left:   20f);

    canvas.Append(innerPanel);
    Append(canvas);
}
```

У цьому випадку:

```csharp
canvas.StyleLayout.JustifyContent = UIExAlignment.Center;
canvas.StyleLayout.AlignItems = UIExAlignment.Center;
```

Ця частина коду вказує на те, що елементи всередині `canvas` мають бути центровані.<br>
Це означає, що координати зовнішньої області мають бути:

1. `outer-X`: `(ширина внутрішньої області canvas) / 2f - (ширина зовнішньої області innerPanel) / 2f`.
2. `outer-Y`: `(висота внутрішньої області canvas) / 2f - (висота зовнішньої області innerPanel) / 2f`.<br>

Тоді центр зовнішньої області `innerPanel` буде точно по центру.<br>

Але звичайна область `innerPanel` починається на `outer-X - 20px` і на `outer-Y - 10px`.<br>
Це означає, що на екрані `innerPanel` буде відображатися на `20px` правіше та на `10px` нижче.<br>

Водночас, якщо ми вкажемо:

```csharp
innerPanelStyle.Margin = new(
        pixels:       true, 
        right:        10f, 
        bottom:       20f);
```

Ми побачимо, що елемент ідеально центрований на екрані.<br>
Уся справа в тому, що в цій моделі компонування `Margin.Right` і `Margin.Bottom` не змінюють `X/Y` області елемента.<br>
Вони впливають тільки на розмір зовнішньої області.<br>
А отже координати в цьому прикладі `X/Y` у зовнішньої та звичайної області збігаються.<br>

<h2 align="center">Схрещування <code>Canvas tModLoader</code> та елементів компонування <code>UIExLayout</code></h2>

Головне, що вам потрібно знати під час використання `UIExLayout` — він не підтримує використання наступних полів `UIElement`:<br>

* `Left`;
* `Top`;
* `Width`;
* `Height`;
* `MarginTop`;
* `MarginLeft`;
* `MarginBottom`;
* `MarginRight`;
* `HAlign`;
* `VAlign`. <br>Використання цих значень для елементів усередині компоновщика призводитиме до неправильного компонування.

`StyleLayoutChild` — визначає власні поля для цих значень `UIElement`:

```csharp
public class StyleLayoutChild : Base.StyleLayoutChildBase
{
	/* ... */
	public UIExThickness Margin = new();
	/* ... */
}
```

`Margin` має тип `UIExThickness`. У ньому відступи являють собою тип `StyleDimension`

```csharp
public StyleDimension Left = StyleDimension.Empty;
public StyleDimension Top = StyleDimension.Empty;
public StyleDimension Right = StyleDimension.Empty;
public StyleDimension Bottom = StyleDimension.Empty;
```

Якщо деякі зі значень `Margin` вказані у відсотках — це вважатиметься відсотком від розміру, визначеного контейнером компонування. Наприклад:

* Для `UIExStackPanel` відсотки обчислюються від усього розміру контейнера.
* Для `UIExGrid` відсотки обчислюються від розміру комірки, у яку поміщено елемент.

<br>

`HAlign` і `VAlign` не використовуються цією бібліотекою в тому вигляді, в якому вони визначені в **tModLoader**. Замість цього використовується механізм `JustifyContent`, `AlignItems`, `JustifySelf`, `AlignSelf`, принцип роботи якого описаний вище.

Наступні поля `UIElement` використовуються у звичайному режимі та не мають аналогів у цій бібліотеці:

* `PaddingLeft`
* `PaddingRight`
* `PaddingTop`
* `PaddingBottom`
* `MinWidth`
* `MaxWidth`
* `MinHeight`
* `MaxHeight`<br><br>

Ще кілька слів про `PaddingLeft`, `PaddingRight`, `PaddingTop`, `PaddingBottom`.<br>
Деякі значення **стилів візуального відображення** або **візуальних стилів елементів від tModLoader** самостійно керують цими значеннями.<br>
Докладніше дивіться у статті 3-го розділу: «клас `UIExElement`».

Що робити, якщо ви все ж хочете використовувати стандартні значення для `Margin`, `HAlign`, `VAlign`?
У цьому випадку ви можете використовувати `UIElement-обгортку`. Припустимо, у нас зараз є код **БЕЗ** використання цих полів:

```csharp
UIPanel panel = new();
SetPrecentSize(panel, left: 0.2f, top: 0.2f, width: 0.6f, height: 0.6f);

UIExStackPanel stackPanel = new();
stackPanel.Stretch();
stackPanel.StyleLayout.JustifyContent = UIExAlignment.Stretch;
stackPanel.StyleLayout.Alignment = UIExAlignment.Stretch;

UIPanel panel1 = new();
UIPanel panel2 = new();
UIPanel panel3 = new();

Append(panel);

panel.Append(stackPanel);

stackPanel.Append(panel1);
stackPanel.Append(panel2);
stackPanel.Append(panel3);
```

У цьому випадку у нас є:

1. `UIPanel` (panel) розміром у 80% вікна та розташована по центру екрана.
2. `UIExStackPanel` (stackPanel) розміром у 100%. Розміщена в panel.
3. `UIPanel` (panel1, panel2, panel3) розміром у 33.(3)% stackPanel. Розміщені в stackPanel.

Тепер ми хочемо задати для panel2 властивості `MarginTop = 10f;`
Для цього обгорнемо його в `UIElement` (або будь-який клас-нащадок).

```csharp
// "UIPanel panel2 = new();" з минулого коду замінимо на код нижче:
UIPanel panel2 = new();
SetPrecentSize(panel2, 0f, 0f, 1f, 1f);
panel2.MarginTop = 10f;

UIElement wrapElement = new();
wrapElement.Append(panel2);



// "stackPanel.Append(panel2);" з минулого коду замінимо на:
stackPanel.Append(wrapElement);
```

Тепер компоновщик `UIExStackPanel` керуватиме розташуванням і розміром `wrapElement`, а `panel2` перебуватиме всередині обгортки та компонуватиметься за допомогою стандартних методів **tModLoader**

---

Для спрощення створення `UIElement-обгорток` клас `UIExLayout` надає статичні методи `Wrap`:

```csharp
public static TUIElement Wrap<TUIElement>(UIElement element, bool stretch = false, bool center = false)
    where TUIElement : UIElement, new()
        => Wrap(element, new TUIElement(), stretch, center);

public static TUIElement Wrap<TUIElement>(UIElement element, TUIElement wrapElement, bool stretch = false, bool center = false)
    where TUIElement : UIElement
{
    if (stretch)
    {
        element.Width.Set(0f, 1f);
        element.Height.Set(0f, 1f);
    }

    if (center)
    {
        element.HAlign = 0.5f;
        element.VAlign = 0.5f;
    }

    wrapElement.Append(element);
    return wrapElement;
}
```

Метод сам створює обгортку для заданого елемента та повертає її.<br>
Тепер давайте замінимо попередній код на метод Wrap.

```csharp
// "UIPanel panel2 = new();" з передостаннього коду замінимо на:
UIPanel panel2 = new();
panel2.MarginTop = 10f;

var wrapElement = UIExLayout.Wrap<UIElement>(panel2, stretch: true, center: false);



// "stackPanel.Append(panel2);" з передостаннього коду замінимо на:
stackPanel.Append(wrapElement);
```

Що робить цей код:

1. Звертається до статичного методу `Wrap` класу `UIExLayout`.
2. Як універсальний тип передається `UIElement`. Це тип користувацького інтерфейсу, у який буде обгорнуто наш елемент.
3. Перший аргумент (`panel2`) — наш `UIElement` або нащадок, який має бути обгорнутий.
4. Другий аргумент (`stretch: true`) — прапорець, що вказує, що потрібно розтягнути об'єкт, який обгортається, по всій області обгортки. При `true` для `panel2` будуть встановлені значення: `Width.Set(0f, 1f)`, `Height.Set(0f, 1f)`.
5. Третій аргумент (`center: false`) — прапорець, що вказує, що потрібно розташувати об'єкт, який обгортається, по центру області обгортки. При `true` для `panel2` будуть встановлені значення `HAlign = 0.5f; VAlign = 0.5f`.

---

<h2 align="center">Метод <code>Stretch()</code></h2>

Клас `UIExLayout` реалізує метод `Stretch()`:

```csharp
public virtual void Stretch()
{
	Top.Set(0f, 0f);
	Left.Set(0f, 0f);
	Height.Set(0f, 1f);
	Width.Set(0f, 1f);
}
```

Як видно з коду, цей метод просто розтягує контейнер за розміром усієї області батьківського елемента.<br>

Пам'ятайте! Значення, які встановлює цей метод, використовують тільки **НЕ** компоновщики. Тому цей метод нічого не робить у такій ситуації (другий виклик методу):

```csharp
UIExCanvas canvas = new();
Append(canvas);

canvas.Stretch();

///////////////////////

UIExStackPanel stackPanel = new();
canvas.Append(stackPanel);

stackPanel.Stretch();

```

1. `canvas` і `stackPanel` викликали метод `Stretch()`.
2. `canvas` доданий безпосередньо всередину `UIState`, який використовує стандартні для **tModLoader** способи розміщення / розміри.

   * Відповідно, метод `Stretch` працює повноцінно.
3. `stackPanel` доданий усередину `canvas`, який **НЕ** використовує стандартні значення `Top`, `Left`, `Width`, `Height`.

   * Відповідно, метод `Stretch` нічого не робить для `stackPanel`.

<h2 align="center">Відображення допоміжних ліній</h2>

Клас `UIExLayout` додає поля:

```csharp
public bool ShowLayoutLines = false;
public float LayoutLinesThickness = 1f;
public Color LayoutLinesColor = Color.LightGray;
```

* `ShowLayoutLines` — вказує, що після компонування потрібно відображати допоміжні лінії поверх елемента.
* `LayoutLinesThickness` — розмір допоміжних ліній. Не використовується, якщо `ShowLayoutLines == false`.
* `LayoutLinesColor` — колір допоміжних ліній. Не використовується, якщо `ShowLayoutLines == false`.

  <br>

І хоча ці поля використовують усі контейнери компонування, те, за яким принципом вони будуть малюватися, відрізняється у різних контейнерів.<br>

```csharp
UIExStackPanel stackPanel = new();
UIExGrid grid = new();
stackPanel.ShowLayoutLines = true; // лінії будуть виведені у вигляді Rectangle() навколо виділеного простору для кожного елемента.
grid.ShowLayoutLines = true; // лінії будуть виведені у вигляді сітки.
```

`UIExLayout` реалізує методи:

```csharp
public void SetLayoutLinesInfoForBranch(bool state, float? thickness = null, Color? color = null) { /* ... */ }
public void SetLayoutLinesInfoForTree(bool state, float? thickness = null, Color? color = null) { /* ... */ }
```

* `SetLayoutLinesInfoForBranch` встановлює передані (not null) значення для поточного елемента та всіх його нащадків, які наслідують клас `UIExLayout`
* `SetLayoutLinesInfoForTree` шукає кореневий батьківський елемент і викликає для нього метод `SetLayoutLinesInfoForBranch`

<br>Ці лінії **НЕ** є частиною UI. Вони малюються безпосередньо поверх `UIExLayout`.<br>
