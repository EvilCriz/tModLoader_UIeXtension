<h2 align="center">Зменшення кількості макетів</h1>

**tModLoader** Відображує розміри кожної клітки для відкритого інтерфейсу. `UIElement` Ваш інтерфейс буде викликаний методом. `Recalculate`.
<br>

Уявіть, що у нас є інтерфейс користувача з елементами *1000*, *400* з яких є елементи макета, що означає, що кожен кадр для всіх елементів *1000* буде викликано. `Recalculate`А після перерахунку також зміниться макет елементів, що означає, що крім рекалькуляції розмірів *1000 * 1000 *, ми також маємо *400 * алгоритми для макетування елементів, які, як ви можете бачити, зроблять цей інтерфейс (і, отже, ця бібліотека) невидимий.
<br><br>

Ця бібліотека вирішує цю проблему наступним чином:<br>
Кожен контейнер макета запам'ятовує:
- Ваш розмір на останньому дзвінку. `Recalculate`.
- Список елементів останнього виклику `Recalculate`.
- Розміри елементів в останньому дзвінку `Recalculate`.
- Контейнерні стилі макета.
- Стилі верстки відстібних елементів.

Якщо:
1. Розмір контейнера не змінився.
2. Елементи всередині контейнера не змінилися.
3. Розмір компонентів всередині контейнера не змінюється.
4. Стилі контейнера/вигорання не змінені.<br>

Розмітка не працює.
<br>

Інформація, яку не може бути написана, тому що це все зроблено будівельником, але потім є наступна проблема.
Уявіть наступний код.

```csharp
UIExStackPanel stackPanel = new();
UIPanel panel1 = new();

// для панелі1 і всіх його нащадків (які не в цьому прикладі) називають методом `Recalculate`.
// але stackPanel Не знаю, що додано новий елемент.
// tModLoader Не можна дізнатися про подію додавання елемента в інший спосіб.
stackPanel.Append(panel1); 


// в цьому пункті називається `Recalculate()` і `RecalculateLayout()`Перевірити елементи і розміри. Виконується весь цикл макета.
Append(stackPanel);


// Увійти stackPanel Додано новий елемент. stackPanel Він не знає, що.
// Однак він вже зберігає список елементів після попереднього макета.
// наступна куртка stackPanel спровокований `Recalculate`.
// Контейнер визначає, що товар змінився. Весь цикл макета виконується.
UIPanel panel2 = new();
stackPanel.Append(panel2); 
```

<br>

Як видно в коді вище: `stackPanel` Я підрахував макет двічі, хоча насправді він повинен це зробити лише 1 раз.
Існує два рішення для цієї проблеми:

<br>

1. Забезпечити, що елементи завжди додаються до посилання **ДОРОСЛИЙ** Як до батьківського елементу додається сам зв'язувач.
2. Спосіб використання `BeginLayoutPreparation` і `EndLayoutPreparation`які ми обговорюємо деталі нижче.

----

```csharp
public static void BeginLayoutPreparation(UIState state)
	=> _statesPreparationTable.TryAdd(state, _preparationStateMarker);

public static void EndLayoutPreparation(UIState state)
{
    ResetСurrentRecalculateLayoutDelayMsBranch(state);
    ResetLastLayoutInfoForBranch(state);

    if (_statesPreparationTable.TryGetValue(state, out _))
        _statesPreparationTable.Remove(state);

    state.Recalculate();
}
```

- Методика `BeginLayoutPreparation(UIState state)` перевалка `UIState` стільниця `_statesPreparationTable`.
- З моменту виклику цього методу `RecalculateLayout` Не буде втілюватися (не в будь-якій точці світу). `UIState`) перед тим, як називатися `EndLayoutPreparation`
<br>

- Методика `EndLayoutPreparation(UIState state)` згорнути `UIState` стільниця `_statesPreparationTable`.
- Відтепер, дія `BeginLayoutPreparation` Він знову зупиняється і знову працює макет. `UIState`.
- `ResetLastLayoutInfoForBranch` Всі нащадки `UIState` Неприємний **одномісний** Наступна модель, інформація про яку згадувалися раніше:
  - Ваш розмір на останньому дзвінку. `Recalculate`.
  - Список елементів останнього виклику `Recalculate`.
  - Розміри елементів в останньому дзвінку `Recalculate`.
  - Стиль розташування контейнера на останньому дзвінку `Recalculate`.
  - Стилі макетування вкладених елементів на останньому виклику `Recalculate`.
- `ResetСurrentRecalculateLayoutDelayMsBranch` скидання для всіх нащадків `UIState` Промисловість `СurrentRecalculateLayoutDelayMs`, які будуть розглянуті нижче.
<br><br>

Ми будемо перезаписати попередній код з новою інформацією:
```csharp
UIExLayout.BeginLayoutPreparation(this);

UIExStackPanel stackPanel = new();
UIPanel panel1 = new();

// для панелі1 і всіх його нащадків (які не в цьому прикладі) називають методом `Recalculate`.
// але stackPanel Не знаю, що додано новий елемент.
// tModLoader Не можна дізнатися про подію додавання елемента в інший спосіб.
stackPanel.Append(panel1);


// в цьому пункті називається `Recalculate()` і `RecalculateLayout()`.
// `ExamplePanelUI` вся в соку `_statesPreparationTable`.
// Перевірка елементів і розмірів не здійснюється.
// Склад елементів не відбувається.
Append(stackPanel);


// Увійти stackPanel Додано новий елемент. stackPanel Він не знає, що.
// Не зберігайте список елементів після попереднього макета.
// Тому не було макета до цього.
UIPanel panel2 = new();
stackPanel.Append(panel2);


// `ExamplePanelUI` скидання `_statesPreparationTable`.
// Всі інші обмеження макета ігноруються в цій рекомпозиції.
// для дочок `ExamplePanelUI`.
// Регуляція розмірів і рекомпозиція всіх нащадків `ExamplePanelUI`.
UIExLayout.EndLayoutPreparation(this); 
```

----

Але навіть в цьому випадку всі перевірки змін в макеті будуть проводитися кожен кадр.<br>
Ідеальне рішення буде після виклику. `UIExLayout.EndLayoutPreparation(this);` Зворотній дзвінок `UIExLayout.BeginLayoutPreparation(this);`.<br>
У цьому випадку посилання не намагатиметься перевірити зміни самої інформації.<br>
У цьому випадку відповідальність за виклик життєвого циклу макета лежить з кінцевим користувачем.<br>
Це означає, що кінцевий користувач самостійно контролює, коли потрібно перенести елементи.<br>
Після цього метод знову називається: `UIExLayout.EndLayoutPreparation(this);`а потім знову `UIExLayout.BeginLayoutPreparation(this);`

----

Ще однією проблемою є розтягування контейнера або його дочок, в якому випадку розміри зміняться весь час, і в результаті кожен каркас буде перепланований.<br><br>
Існує два рішення для цієї проблеми:<br>
1. Використання інструментів. `BeginLayoutPreparation` і `EndLayoutPreparation` Тепер, якщо ви знаєте, що ви будете змінювати багато прямо зараз, ви можете тимчасово відключити макет.
2. Використовуйте його. `RecalculateLayoutDelayMs`, `SetRecalculateLayoutDelayMsBranch` або `SetRecalculateLayoutDelayMsState`:<br>
```csharp
public class RecalculateLayoutStateDelay
{
    public int? DelayMs = 0;
}

public abstract partial class UIExLayout : UIExElement
{
    private static readonly System.Runtime.CompilerServices.
        ConditionalWeakTable<UIState, RecalculateLayoutStateDelay> _statesRecalculateDalayMs = new();

    public int RecalculateLayoutDelayMs = 0;

    public static void SetRecalculateLayoutDelayMsBranch(UIElement element, int ms)
    {
        if (element is UIExLayout layout)
            layout.RecalculateLayoutDelayMs = ms;

        foreach (var child in element.Children)
            SetRecalculateLayoutDelayMsBranch(child, ms);
    }


    public static void SetRecalculateLayoutDelayMsState(UIState state, int? delayMs)
    {
        if (_statesRecalculateDalayMs.TryGetValue(state, out RecalculateLayoutStateDelay delay))
            delay.DelayMs = delayMs;
        else
        {
            RecalculateLayoutStateDelay delayNew = new() { DelayMs = delayMs };
            _statesRecalculateDalayMs.Add(state, delayNew);
        }
    }

    public static int? GetRecalculateLayoutDelayMsState(UIState state)
    {
        if (_statesRecalculateDalayMs.TryGetValue(state, out RecalculateLayoutStateDelay delay))
            return delay.DelayMs;

        return null;
    }
}
```

Ці налаштування визначаються в класі `UIExLayout`Вони відповідають за мінімальну затримку в мілісекундах в макеті конкретного елемента.<br>
Що таке, після того, як рекалькулятор перерахував макет, він встановлює затримку до наступного макета в кількості `N` ms.<br>
- Зареєструватися `GetRecalculateLayoutDelayMsState(firstParentState) is not null` Деле буде визначено цим методом.
- Зареєструватися `GetRecalculateLayoutDelayMsState(firstParentState) is null` - визначення затримки `RecalculateLayoutDelayMs`.
- Методика `SetRecalculateLayoutDelayMsState(UIState state, int? delayMs)` Це дозволяє визначити затримку певного `UIState`Якщо у вас є `delayMs` Закупівля `null` - Видаляє затримку для перерахунку `UIState`.
- Методика `SetRecalculateLayoutDelayMsBranch` дозволяє встановити затримку `RecalculateLayoutDelayMs` елементи пропускаються і до всіх нащадків.
