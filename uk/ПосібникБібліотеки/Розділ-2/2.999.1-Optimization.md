<h2 align="center">Зменшення кількості компоновок</h1>

**tModLoader** перераховує розміри кожен тік для відкритого інтерфейсу. Це означає, що для кожного `UIElement` вашого інтерфейсу буде викликатися метод `Recalculate`. <br>

Уявімо, що у нас є користувацький інтерфейс із *1000* елементів, *400* з яких — елементи компоновки. Це означає, що кожного кадру для всіх *1000* елементів буде викликатися `Recalculate`. А після перерахунку розмірів також змінюватиметься компоновка елементів. Отже, крім *1000* перерахунків розмірів, у нас також буде *400* алгоритмів компоновки елементів. Як ви розумієте, це зробить цей інтерфейс (і, як наслідок, цю бібліотеку) нежиттєздатним. <br><br>

Ця бібліотека вирішує цю проблему наступним чином:<br>
Кожен контейнер компоновки запам'ятовує:

* Свій розмір під час останнього виклику `Recalculate`.
* Список елементів під час останнього виклику `Recalculate`.
* Розміри елементів під час останнього виклику `Recalculate`.
* Стилі компоновки контейнера.
* Стилі компоновки вкладених елементів.

Якщо:

1. Розмір контейнера не змінився.
2. Елементи всередині контейнера не змінилися.
3. Розміри елементів усередині контейнера не змінилися.
4. Стилі контейнера/елементів не змінилися.<br>

Компоновка не виконується. <br>

Інформацію вище можна було б не писати, адже це все робить сам компоновщик. Але тут виникає наступна проблема.
Уявімо наступний код.

```csharp
UIExStackPanel stackPanel = new();
UIPanel panel1 = new();

// для panel1 та всіх його нащадків (яких у цьому прикладі немає) було викликано метод `Recalculate`.
// але сам stackPanel поки нічого не знає про те, що до нього додано новий елемент.
// tModLoader не дає можливості дізнатися про подію додавання елемента всередину іншого.
stackPanel.Append(panel1); 


// у цей момент викликається `Recalculate()` і `RecalculateLayout()`. Перевіряються елементи та розміри. Виконується весь цикл компоновки.
Append(stackPanel);


// до stackPanel додано новий елемент. Але stackPanel про це не знає.
// тим не менш він уже зберігає список елементів після попередньої компоновки.
// під час наступного тіку у stackPanel викликається `Recalculate`.
// контейнер визначає, що елемент змінився. Виконується весь цикл компоновки.
UIPanel panel2 = new();
stackPanel.Append(panel2); 
```

<br>

Як видно з коду вище: `stackPanel` перерахував компоновку двічі, хоча фактично йому потрібно було зробити це лише 1 раз.
Вирішення цієї проблеми два:

<br>

1. Стежити за тим, щоб елементи завжди додавалися до компоновщика **ДО** того, як сам компоновщик буде доданий до батьківського елемента.
2. Використовувати методи `BeginLayoutPreparation` і `EndLayoutPreparation`, про які детально поговоримо нижче.

---

```csharp
public static void BeginLayoutPreparation(UIState state)
	=> _statesPreparationTable.TryAdd(state, _preparationStateMarker);

public static void EndLayoutPreparation(UIState state)
{
    ResetСurrentRecalculateLayoutDelayMsBranch(state);
    ResetLastLayoutInfoForBranch(state);

    if (_statesPreparationTable.TryGetValue(state, out _))
        _statesPreparationTable.Remove(state);

    state.Recalculate();
}
```

* Метод `BeginLayoutPreparation(UIState state)` заносить переданий `UIState` до таблиці `_statesPreparationTable`.

* Від моменту виклику цього методу `RecalculateLayout` не буде виконаний (ніде в цьому `UIState`) до виклику `EndLayoutPreparation`

  <br>

* Метод `EndLayoutPreparation(UIState state)` видаляє переданий `UIState` із таблиці `_statesPreparationTable`.

* Від цього моменту дія `BeginLayoutPreparation` припиняється і компоновка знову працює в цьому `UIState`.

* `ResetLastLayoutInfoForBranch` змушує всіх нащадків `UIState` ігнорувати, під час **однієї** наступної компоновки, інформацію, про яку згадувалося раніше:

  * Свій розмір під час останнього виклику `Recalculate`.
  * Список елементів під час останнього виклику `Recalculate`.
  * Розміри елементів під час останнього виклику `Recalculate`.
  * Стиль компоновки контейнера під час останнього виклику `Recalculate`.
  * Стилі компоновки вкладених елементів під час останнього виклику `Recalculate`.

* `ResetСurrentRecalculateLayoutDelayMsBranch` скидає для всіх нащадків `UIState` поле `СurrentRecalculateLayoutDelayMs`, про яке йтиметься нижче. <br><br>

Перепишемо попередній код з урахуванням нової інформації:

```csharp
UIExLayout.BeginLayoutPreparation(this);

UIExStackPanel stackPanel = new();
UIPanel panel1 = new();

// для panel1 та всіх його нащадків (яких у цьому прикладі немає) було викликано метод `Recalculate`.
// але сам stackPanel поки нічого не знає про те, що до нього додано новий елемент.
// tModLoader не дає можливості дізнатися про подію додавання елемента всередину іншого.
stackPanel.Append(panel1);


// у цей момент викликається `Recalculate()` і `RecalculateLayout()`.
// `ExamplePanelUI` знаходиться в таблиці `_statesPreparationTable`.
// перевірка елементів та розмірів НЕ виконується.
// компоновка елементів НЕ відбувається.
Append(stackPanel);


// до stackPanel додано новий елемент. Але stackPanel про це не знає.
// він НЕ зберігає список елементів після попередньої компоновки.
// оскільки жодної компоновки до цього не було.
UIPanel panel2 = new();
stackPanel.Append(panel2);


// `ExamplePanelUI` видаляється з таблиці `_statesPreparationTable`.
// усі інші обмежувачі компоновки ігноруються під час цієї перекомпоновки
// для дочірніх елементів `ExamplePanelUI`.
// відбувається перерахунок розмірів і перекомпонування всіх нащадків `ExamplePanelUI`.
UIExLayout.EndLayoutPreparation(this); 
```

---

Але навіть у цьому випадку всі перевірки на зміни компоновки проводитимуться кожен кадр.<br>
Ідеальним рішенням буде після виклику `UIExLayout.EndLayoutPreparation(this);` повторно викликати `UIExLayout.BeginLayoutPreparation(this);`.<br>
У цьому випадку компоновщик навіть не намагатиметься самостійно перевіряти зміни інформації.<br>
У цьому випадку відповідальність за виклик життєвого циклу компоновки покладається на кінцевого користувача.<br>
Це означає, що кінцевий користувач самостійно відстежує, коли компоновщик має виконати перекомпонування елементів.<br>
Тоді знову викликаються методи: `UIExLayout.EndLayoutPreparation(this);`, а потім знову `UIExLayout.BeginLayoutPreparation(this);`

---

Ще одна проблема: розтягування контейнера або його дочірніх елементів. У цьому випадку розміри змінюватимуться весь час і, як наслідок, кожен кадр відбуватиметься перекомпонування.<br><br>
Вирішення цієї проблеми два:<br>

1. Використовувати інструменти `BeginLayoutPreparation` і `EndLayoutPreparation`, про які ми говорили вище. Якщо ви знаєте, що зараз елемент часто змінюватиме розміри, ви можете тимчасово вимкнути компоновку.
2. Використовувати `RecalculateLayoutDelayMs`, `SetRecalculateLayoutDelayMsBranch` або `SetRecalculateLayoutDelayMsState`:<br>

```csharp
public class RecalculateLayoutStateDelay
{
    public int? DelayMs = 0;
}

public abstract partial class UIExLayout : UIExElement
{
    private static readonly System.Runtime.CompilerServices.
        ConditionalWeakTable<UIState, RecalculateLayoutStateDelay> _statesRecalculateDalayMs = new();

    public int RecalculateLayoutDelayMs = 0;

    public static void SetRecalculateLayoutDelayMsBranch(UIElement element, int ms)
    {
        if (element is UIExLayout layout)
            layout.RecalculateLayoutDelayMs = ms;

        foreach (var child in element.Children)
            SetRecalculateLayoutDelayMsBranch(child, ms);
    }


    public static void SetRecalculateLayoutDelayMsState(UIState state, int? delayMs)
    {
        if (_statesRecalculateDalayMs.TryGetValue(state, out RecalculateLayoutStateDelay delay))
            delay.DelayMs = delayMs;
        else
        {
            RecalculateLayoutStateDelay delayNew = new() { DelayMs = delayMs };
            _statesRecalculateDalayMs.Add(state, delayNew);
        }
    }

    public static int? GetRecalculateLayoutDelayMsState(UIState state)
    {
        if (_statesRecalculateDalayMs.TryGetValue(state, out RecalculateLayoutStateDelay delay))
            return delay.DelayMs;

        return null;
    }
}
```

Ці налаштування визначені в класі `UIExLayout`. Вони відповідають за мінімальну затримку в мілісекундах під час компоновки певного елемента.<br>
Тобто після того, як компоновщик перерахував компоновку, він встановлює затримку перед наступною компоновкою в розмірі `N` ms.<br>

* Якщо `GetRecalculateLayoutDelayMsState(firstParentState) is not null` — затримку визначатиме цей метод.
* Якщо `GetRecalculateLayoutDelayMsState(firstParentState) is null` — затримку визначатиме `RecalculateLayoutDelayMs`.
* Метод `SetRecalculateLayoutDelayMsState(UIState state, int? delayMs)` дозволяє встановити затримку для певного `UIState`. Якщо в `delayMs` передано `null` — прибирає затримку для переданого `UIState`.
* Метод `SetRecalculateLayoutDelayMsBranch` дозволяє встановити затримку `RecalculateLayoutDelayMs` переданому елементу та всім нащадкам.
