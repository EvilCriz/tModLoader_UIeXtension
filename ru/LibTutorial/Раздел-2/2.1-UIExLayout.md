<h1 align="center">Класс <i>UIExLayout</i>. Основы компоновки</h1>

Класс `UIExLayout` является базовым классом для элементов компоновки. Он реализует:
1. Жизненный цикл компоновки элементов.
2. Стили компоновки контейнера, которые поддерживает любой элемент компоновки.
3. Организует хранения стилей компоновки вложенных элементов и доступ к ним.
4. Вспомогательные статические методы `Wrap`, которые будут описаны в данной статье.
5. Инструменты оптимизации, часть из которых отдается во внешнее управление (из-за внутренний ограничений **tModLoader**).
<br>

- В данной статье будут разобраны эти пункты, кроме: 
- Пункта 1 — жизненный цикл компоновки. Будет разбираться в отдельной части данного раздела. Вам нужно понимать жизненный цикл, только если вы планируете писать свой компоновщик на основе данной библиотеки.
- Пункта 5 — инструменты оптимизации. Будут разбираться в отдельной части ванного раздела.
- Пункта 3 — частично будет разобран в данной статье, частично - в отдельной части ванного раздела.

<h2 align="center">Стили компоновки контейнера и вложенных элементов</h2>

Класс `UIExLayout` определяет свойство:

```csharp
public Styles.StyleLayoutContainer StyleLayout { get; set; }
```

Данное поле содержит стили компоновки, которые реализует любой контейнер компоновки.<br>

Тип данных `Styles.StyleLayoutContainer` имеет следующую реализацию:
```csharp
public class StyleLayoutContainer() : IStyleLayoutContainer, IStyleCopyManager<StyleLayoutContainer>
{
    public Enums.Orientation Orientation = Enums.Orientation.Vertical;
    public Enums.Alignment JustifyContent = Enums.Alignment.Auto;
    public Enums.Alignment AlignItems = Enums.Alignment.Auto;

    public void Set(Enums.Orientation orientation, Enums.Alignment justifyContent, Enums.Alignment alignItems) { /* ... */ }
    public void Copy(StyleLayoutContainer style) { /* ... */ }
    public StyleLayoutContainer GetCopy()
    {
        StyleLayoutContainer copy = new();
        copy.Copy(this);
        return copy;
    }
}
```

- `Orientation` определяет, какая ось будет считаться главной для контейнера, а какая - поперечной.
- `JustifyContent` и `AlignItems` указывает, как будут выравниваться элементы по главной и поперечной осям. `Enums.Alignment` может принимать следующие значения:
  - `Start`: выравнивание по началу главной / поперечной оси.
  - `Center`: выравнивание по центру главной / поперечной оси.
  - `End`: выравнивание по концу главной / поперечной оси.
  - `Stretch`: растягивает по главной / поперечной оси.
  - `Auto`: данное значение используют только вложенные в контейнер элементы (см. ниже). Использование данного значения для `JustifyContent` и `AlignItems` будет приравнено к значению `Start`.

Также определены методы `Set`, `Copy`, `GetCopy`. Данные методы имеет абсолютно любой класс стилей в данной библиотеке.
- `void Set`: требует установить все значения, которые определяет данный конкретный стиль стиль.
- `void Copy(TStyle)`: принимает объект того же класса, в котором определен данный метод. Копирует значения всех полей переданного аргумента в текущий объект стиля (пример использования данного метода вы можете посмотреть в методе `GetCopy()` выше.
- `TStyle GetCopy()`: создают и возвращают копию объекта, для которого был вызван данный метод.

----

Это был стиль самого контейнера. Но все вложенные в `UIExLayout` элементы могут так же использовать класс стилей: `StyleLayoutChild`<br>
Для других (но не обязательно для всех) элементов компоновки будет аналогичный класс стилей, но с названием самого контейнера в конце.<br>
Например:

- Для `UIExGrid` — `StyleLayoutChildGrid`
- Для `UIExFlex` — `StyleLayoutChildFlex`

Чтобы получить конкретный стиль для дочернего элемента определены методы:

```csharp
// Для всех UIExLayout:
public Styles.StyleLayoutChild GetOrRegisterStyleLayoutChild(UIElement element)
    => GetOrRegisterStyleLayoutChild<Styles.StyleLayoutChild>(element);

// Для всех UIExGrid
public Styles.StyleLayoutChildGrid GetOrRegisterStyleLayoutChildGrid(UIElement element)
    => GetOrRegisterStyleLayoutChild<Styles.StyleLayoutChildGrid>(element);

// Для всех UIExFlex
public Styles.StyleLayoutChildFlex GetOrRegisterStyleLayoutChildFlex(UIElement element)
    => GetOrRegisterStyleLayoutChild<Styles.StyleLayoutChildFlex>(element);
```

При вызове метода `GetOrRegisterStyleLayoutChild(UIElement element)` будет возвращен его стиль `Styles.StyleLayoutChild`, который хранится в специальной таблице в классе `UIExLayout`.<br>
Если такого стиля для данного метода не было в таблице ранее - он будет создан и помещен в таблицу.<br>
<i>Рекомендация</i>: старайтесь минимизировать использование `GetOrRegisterStyle-методов`. Операция довольно затратна, поэтому значительно лучше получать стиль 1 раз, сохранять стиль и менять уже сохраненный объект.

```csharp
// панель, которая будет получать стили.
UIPanel panel = new();

// компоновщик, который будет регистрировать стили для UIPanel
UIGrid grid = new();
grid.Stretch(); // указывает, что grid должен занимать 100% родительского контейнера.

// регистрация стиля для UIPanel, который определен в UIExLayout и закреплен за конкретным grid 
Styles.StyleLayoutChild style = grid.GetOrRegisterStyleLayoutChild(panel);

// регистрация стиля для UIPanel, который определен в UIExGrid и закреплен за конкретным grid 
Styles.StyleLayoutChildGrid styleGrid = grid.GetOrRegisterStyleLayoutChildGrid(panel);

style.WithoutLayout = true; // будет разбираться ниже.
styleGrid.Row = 1;
styleGrid.Column = 1;
styleGrid.RowSpan = 1;
```

Также существуют аналогичные `Set-методы`, которые позволяют сразу установить зарегистрировать класс стиля для определенного `UIElement` внутри контейнера:

```csharp
// Для всех UIExLayout:
public void SetStyleLayoutChild(UIElement element, Styles.StyleLayoutChild style)
    => SetStyleLayoutChild<Styles.StyleLayoutChild>(element, style);

// Для всех UIExGrid
public void SetStyleLayoutChildGrid(UIElement element, Styles.StyleLayoutChildGrid style)
    => SetStyleLayoutChild<Styles.StyleLayoutChildGrid>(element, style);

// Для всех UIExFlex
public void SetStyleLayoutChildFlex(UIElement element, Styles.StyleLayoutChildFlex style)
    => SetStyleLayoutChild<Styles.StyleLayoutChildFlex>(element, style);
```

Класс `Styles.StyleLayoutChild` определяет стили компоновки для дочерних элементов контейнера.

```csharp
public class StyleLayoutChild : IStyleLayoutChild, IStyleCopyManager<StyleLayoutChild>
{
    public Enums.Alignment JustifySelf = Enums.Alignment.Auto;
    public Enums.Alignment AlignSelf = Enums.Alignment.Auto;
	
	public Thickness Margin = new();
    public StyleDimension VerticalAlignment = StyleDimension.Empty;
    public StyleDimension HorizontalAlignment = StyleDimension.Empty;

	public bool WithoutLayout = false;

    public void Set(Enums.Alignment justifySelf, Enums.Alignment alignSelf, Thickness margin, StyleDimension verticalAlignment, StyleDimension horizontalAlignment, bool withoutLayout = true) { /* ... */ }
    public void Copy(StyleLayoutChild style) { /* ... */ }
    public StyleLayoutChild GetCopy() { /* ... */ }
}
```

`JustifySelf` и `AlignSelf` определяет, как элемент будет выравниваться по основной / поперечной оси. Выше мы уже разбирали значения `Enums.Alignment`. Кроме значения `Auto`. И для дочерних элементов контейнера это значение является ключевым.<br>

Если у контейнера значение `JustifyContent == Enums.Alignment.Center` - это означает, что все элементы внутри контейнера будут располагаться по центру главной оси. И это правило работает для всех дочерних элементов, у которых значения `JustifySelf == Enums.Alignment.Auto`.<br>

`Auto` для вложенного элемента означает, что он возьмет значение контейнера. Любое другое значение `JustifySelf` переопределит `JustifyContent` для этого конкретного элемента.<br>

Для `AlignSelf` ситуация аналогичная для поперечной оси.<br>

Не все контейнеры используют `JustifySelf` и `AlignSelf`. Например `UIExStackPanel` игнорирует эти значение у вложенных элементов.<br><br>

Про `Margin`, `VerticalAlignment` и `HorizontalAlignment` мы подробнее поговорим ниже.<br>

----

```csharp
public bool WithoutLayout = false;
```

Это поле отвечает за то, будет ли элемент игнорироваться при компоновке.<br>
Все способы изменения размера и расположения для такого элемента остаются стандартными для **tModLoader**
Например: представим, что мы создаем панель для игры в сапера. 
- Должна быть основная панель игры (в которою можно будет добавить игровое поле, настройки и т.д.)
- Само игровое поле.
- И вывод текста "GAME OVER" прям по центру игрового поля.

```csharp
void OnInitialize()
{
	// Пример (кратно урезанный) игры: Сапер

	// Создается панель занимающая 60% экрана и располагающася по центру.
	UIPanel panel = new();
	SetPrecentSize(panel, left: 0.2f, top: 0.2f, width: 0.6f, height: 0.6f); // написанный для примера метод. НЕ определен в самой библиотеке.
	Append(panel);
	
	// Создается панель UniformGrid 10х10 и в нее добавляются кнопки.
	// Сама Grid панель помещается занимает width: 50%; height: 80% от размеров panel.
	int rows = 10, columns = 10;
	UIExUniformGrid grid = new(rows, columns);
	SetPrecentSize(grid, left: 0.25f, top: 0.1f, width: 0.5f, height: 0.8f);
	panel.Append(grid);
	
	// Указываем, что добавленные в UniformGrid кнопки должны занимать 100% размера ячейки.
	grid.StyleLayoutGrid.JustifyContent == Enums.Alignment.Stretch;
	grid.StyleLayoutGrid.AlignItems == Enums.Alignment.Stretch;
	
	for(int row = 0; row < rows; row++)
		for(int column = 0; column < columns; column++)
		{
			UIButton<string> button = new();
			Styles.StyleLayoutChildGrid styleGrid = grid.GetOrRegisterStyleLayoutChildGrid(button);
			styleGrid.Row = row;
			styleGrid.Column = column;
			grid.Append(button);
		}
	
	// Создает текст. Он добавляется в grid.
	UIExTextBlock text = new("GAME OVER");
	Styles.StyleLayoutChildGrid styleLayoutChild = grid.GetOrRegisterStyleLayoutChild(text);
	
	// Указываем, что UniformGrid не должен управлять компоновкой text
	// Это значит, что использоваться будет Canvas tModLoader
	styleLayoutChild.WithoutLayout = true; 
	
	// Указываем, что текст должен быть ровно в центре grid.
	text.HAlign = 0.5f;
	text.VAlign = 0.5f;
	grid.Append(text);
}
```

Если вы хотите для расположения элементов использовать только данную библиотеку, то для данной задачи можно было бы использовать `UIExCanvas`. В этом случае часть кода заменяется.<br>
Эта часть кода:
```csharp
// Создает текст. Он добавляется в grid.
UIExTextBlock text = new("GAME OVER");
Styles.StyleLayoutChildGrid styleLayoutChild = grid.GetOrRegisterStyleLayoutChild(text);

// Указываем, что UniformGrid не должен управлять компоновкой text
// Это значит, что использоваться будет Canvas tModLoader
styleLayoutChild.WithoutLayout = true; 

// Указываем, что текст должен быть ровно в центре grid.
text.HAlign = 0.5f;
text.VAlign = 0.5f;
grid.Append(text);
```

Заменяется на:
```csharp
UIExCanvas canvas = new();
canvas.Stretch();
UIExTextBlock text = new("GAME OVER");

grid.GetOrRegisterStyleLayoutChild(canvas).WithoutLayout = true;

canvas.StyleLayout.JustifyContent = Enums.Aligment.Center;
canvas.StyleLayout.AlignItems = Enums.Aligment.Center;

canvas.Append(text);
grid.Append(canvas);
```

<h2 align="center">Скрещивание <i>Canvas</i> tModLoader и элементов компоновки <i>UIExLayout</i></h1>

Главное, что вам нужно знать при использовании `UIExLayout` — он не поддерживает использования следующих полей `UIElement`:<br>
- `MarginTop`;
- `MarginLeft`;
- `MarginBottom`;
- `MarginRight`;
- `HAlign`;
- `VAlign`.
<br>Использование данных значений для элементов внутри компоновщика будет приводить к неправильной компоновке.

`StyleLayoutChild` — определяет свои поля для этих значений `UIElement`:
```csharp
public class StyleLayoutChild : IStyleLayoutChild, IStyleCopyManager<StyleLayoutChild>
{
	/* ... */
	public Thickness Margin = new();
	public StyleDimension VerticalAlignment = StyleDimension.Empty;
	public StyleDimension HorizontalAlignment = StyleDimension.Empty;
	/* ... */
}
```

`Margin` имеет тип `Thickness`. В нем отступы представляют собой тип `StyleDimension`
```csharp
public StyleDimension Left = StyleDimension.Empty;
public StyleDimension Top = StyleDimension.Empty;
public StyleDimension Right = StyleDimension.Empty;
public StyleDimension Bottom = StyleDimension.Empty;
```

По окончанию компоновки поля `MarginTop`, `MarginLeft`, `MarginRight, `MarginBottom` будут заменены значениями из `Margin` класса `StyleLayoutChild`.<br>

Если какие-то из значений `Margin`, `VerticalAlignment`, `HorizontalAlignment` указаны в процентах - это будет считаться процентом от размера всего контейнера компоновщики.

----

Что делать, если вы все же хотите использовать стандартные значения для `Margin`, `HAlign`, `VAlign`?
В этом случае вы можете использовать `UIElement-обертку`. Допустим, у нас сейчас есть код **БЕЗ** использования этих полей:

```csharp
UIPanel panel = new();
SetPrecentSize(panel, left: 0.2f, top: 0.2f, width: 0.6f, height: 0.6f);

UIExStackPanel stackPanel = new();
stackPanel.Stretch();
stackPanel.StyleLayoutStackPanel.JustifyContent == Enums.Alignment.Stretch;
stackPanel.StyleLayoutStackPanel.Alignment == Enums.Alignment.Stretch;

UIPanel panel1 = new();
UIPanel panel2 = new();
UIPanel panel3 = new();

Append(panel);

panel.Append(stackPanel);

stackPanel.Append(panel1);
stackPanel.Append(panel2);
stackPanel.Append(panel3);
```

В данном случае у нас есть:
1. `UIPanel` (panel) размером в 80% окна и расположенная по центру экрана.
2. `UIExStackPanel` (stackPanel) размером в 100%. Размещена в panel.
3. `UIPanel` (panel1, panel2, panel3) размером с 33.(3)% stackPanel. Размещены в stackPanel.

Теперь мы хотим задать для panel2 свойства `MarginTop = 10f;`
Для этого обернем его в `UIElement` (или любой класс наследник).

```csharp
// "UIPanel panel2 = new();" из прошлого кода заменим на код ниже:
UIPanel panel2 = new();
SetPrecentSize(panel2, 0f, 0f, 1f, 1f);
panel2.MarginTop = 10f;

UIElement wrapElement = new();
wrapElement.Append(panel2);



// "stackPanel.Append(panel2);" из прошлого кода заменим на:
stackPanel.Append(wrapElement);
```

Теперь компоновщик `UIExStackPanel` будет управлять расположением и размером `wrapElement`, а `panel2` будет находится внутри обертки, и компоноваться с помощью стандартных методов **tModLoader**

----

Для упрощения создания `UIElement-оберток` класс `UIExLayout` предоставляет статические методы `Wrap`:

```csharp
public static TUIElement Wrap<TUIElement>(UIElement element, bool stretch = false, bool center = false)
    where TUIElement : UIElement, new()
        => Wrap(element, new TUIElement(), stretch, center);

public static TUIElement Wrap<TUIElement>(UIElement element, TUIElement wrapElement, bool stretch = false, bool center = false)
    where TUIElement : UIElement
{
    if (stretch)
    {
        element.Width.Set(0f, 1f);
        element.Height.Set(0f, 1f);
    }

    if (center)
    {
        element.HAlign = 0.5f;
        element.VAlign = 0.5f;
    }

    wrapElement.Append(element);
    return wrapElement;
}
```

Метод сам создает обертку для заданного элемента и возвращает ее.<br>
Сейчас давайте заменим предыдущий код на метод Wrap.

```csharp
// "UIPanel panel2 = new();" из предпоследнего кода заменим на:
UIPanel panel2 = new();
panel2.MarginTop = 10f;

var wrapElement = UIExLayout.Wrap<UIElement>(panel2, stretch: true, center: false);



// "stackPanel.Append(panel2);" из предпоследнего кода заменим на:
stackPanel.Append(wrapElement);
```

Что делает этот код:
1. Обращается к статическому методу `Wrap` класса `UIExLayout'.
2. В качестве универсального типа передается `UIElement`. Это тип пользовательского интерфейса, в который будет обернут наш элемент.
3. Первый аргумент (`panel2`) - наш `UIElement` или наследник который должен быть обернут.
4. Второй аргумент (`stretch: true`) - флаг, указывающий, что нужно растянуть оборачиваемый объект по всей области обертки. При `true` - для `panel2` будут установлены значения: `Width.Set(0f, 1f)`, `Height.Set(0f, 1f)`.
5. Третий аргумент (`center: false`) - флаг, указывающий, что нужно расположить оборачиваемый объект по центру области обертки. При `true` - для `panel2` будут установлены значения `HAlign = 0.5f; VAlign = 0.5f`.

<h2 align="center">Отображение вспомогательных линий</h2>

Класс `UIExLayout` добавляет поля:
- `public bool ShowLayoutLines = false;` - указывает, что после компоновки нужно отображать вспомогательные линии поверх элемента.
- `public float LayoutLinesThickness = 1f;` - размер вспомогательных линий. Не используется, если `ShowLayoutLines == false`.
- `public Color LayoutLinesColor = Color.LightGray;` - цвет вспомогательных линий. Не используется, если `ShowLayoutLines == false`.
<br>

И хотя данные поля используют все контейнеры компоновки компоновки - то, по какому принципу они будут рисоваться отличаться у разных контейнеров.<br>
```csharp
UIExStackPanel stackPanel = new();
UIExGrid grid = new();
stackPanel.ShowLayoutLines = true; // линии будут выведены в виде Rectangle() вокруг выделенного пространства для каждого элемента.
grid.ShowLayoutLines = true; // линии будут выведены в виде сетки.
```

Данные линии **НЕ** являются частью UI. Они рисуются непосредственно поверх `UIExLayout`.
