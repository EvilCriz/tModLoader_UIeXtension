<h1 align="center">Оптимизация элементов компоновки</h1>

----

В данной статье будут рассмотрены все возможности `UIExLayout` по оптимизации.<br>
Но сперва нужно погрузиться в жизненный цикл интерфейса **tModLoader** и жизненный цикл компоновки `UIExLayout`.<br>
И хотя основная информацию об этом будет в следующей статье, сейчас мы рассмотрим самое необходимое для понимания данной статьи.

----

<h2 align="center">Уменьшение количества компоновок</h1>

**tModLoader** пересчитывает размеры каждый тик для открытого интерфейса. Это значит, что для каждого `UIElement` вашего интерфейса будет вызываться метод `Recalculate`.
<br>

Представим, что у нас есть пользовательский интерфейс с *1000* элементов, *400* из которых - элементы компоновки. Это означает, что каждый кадр для всей *1000* элементов будет вызываться `Recalculate`. А после пересчета размеров также будет меняться компоновка элементов. Значит, что помимо *1000* пересчетов размеров, у нас также будет *400* алгоритмов компоновки элементов. Как вы понимаете, это сделает данный интерфейс (и, как следствие, данную библиотеку) нежизнеспособной.
<br><br>

Данная библиотека решает эту проблему следующим образом:<br>
Каждый контейнер компоновки запоминает:
- Свой размер при последнем вызове `Recalculate`.
- Список элементов при последнем вызове `Recalculate`.
- Размеры элементов при последнем вызове `Recalculate`.

Если:
1. Размер контейнера не изменился.
2. Элементы внутри контейнера не изменились.
3. Размеры элементов внутри контейнера не изменились.<br>

Компоновка не выполняется.
<br>

Информацию выше можно было бы не писать, ведь это все делает сам компоновщик. Но тут возникает следующая проблема.
Представим следующий код.

```csharp
UIExStackPanel stackPanel = new();
UIPanel panel1 = new();

// для panel1 и всех его потомков (которых в этом примере нет) вызвался метод `Recalculate`.
// но сам stackPanel ничего пока ничего не знает о том, что в него добавлен новый элемент.
// tModLoader не дает возможности узнать о событии добавления элемента внутрь другого.
stackPanel.Append(panel1); 


// в этот момент вызывается `Recalculate()` и `RecalculateLayout()`. Проверяются элементы и размеры. Выполняется весь цикл компоновки.
Append(stackPanel);


// в stackPanel добавлен новый элемент. Но stackPanel об этом не знает.
// тем не менее он уже хранит список элементов после предыдущей компоновки.
// при следующем тике у stackPanel вызывается `Recalculate`.
// контейнер определяет, что элемент изменился. Выполняется весь цикл компоновки.
UIPanel panel2 = new();
stackPanel.Append(panel2); 
```

<br>

Как видно в коде выше: `stackPanel` пересчитал компоновку дважды, хотя фактически ему нужно было это сделать только 1 раз.
Решения у данной проблемы два:

<br>

1. Следить за тем, чтобы элементы в компоновщик всегда добавлялись **ДО** того, как сам компоновщик будет добавлен в родительский элемент.
2. Использовать методы `BeginLayoutPreparation` и `EndLayoutPreparation`, о которых подробно поговорим ниже.

----

```csharp
public static void BeginLayoutPreparation() => _layoutPreparation = true;

public static void EndLayoutPreparation(UIExLayout element)
{
    ResetСurrentRecalculateLayoutDelayMsBranch(element);
    ResetLastLayoutInfoForBranch(element);
    _layoutPreparation = false;
    
    element.Recalculate();
}
```

- Метод `BeginLayoutPreparation` устанавливает флаг `_layoutPreparation = true;`.
- С момента вызова данного метода `RecalculateLayout` не будет выполнен (нигде в данном проекте) до вызова `EndLayoutPreparation`
<br>

- Метод `EndLayoutPreparation(UIExLayout element)` устанавливает `_layoutPreparation = false;`
- С этого момента действие `BeginLayoutPreparation` прекращается и компоновка снова работает.
- `ResetLastLayoutInfoForBranch` заставляет себя и всех потомков игнорировать  при **одной** следующей компоновке информацию о которых упоминалось ранее:
  - Свой размер при последнем вызове `Recalculate`.
  - Список элементов при последнем вызове `Recalculate`.
  - Размеры элементов при последнем вызове `Recalculate`.
- `ResetСurrentRecalculateLayoutDelayMsBranch` сбрасывает для себя и всех потомков `СurrentRecalculateLayoutDelayMs` о котором будет идти речь ниже.
<br><br>

Перепишем предыдущий код с учетом новой информации:
```csharp
UIExLayout.BeginLayoutPreparation();

UIExStackPanel stackPanel = new();
UIPanel panel1 = new();

// для panel1 и всех его потомков (которых в этом примере нет) вызвался метод `Recalculate`.
// но сам stackPanel ничего пока ничего не знает о том, что в него добавлен новый элемент.
// tModLoader не дает возможности узнать о событии добавления элемента внутрь другого.
stackPanel.Append(panel1); 


// в этот момент вызывается `Recalculate()` и `RecalculateLayout()`.
// флаг `_layoutPreparation == true`.
// проверка элементов и размеров НЕ выполняется.
// компоновка элементов НЕ происходит.
Append(stackPanel);


// в stackPanel добавлен новый элемент. Но stackPanel об этом не знает.
// он НЕ хранит список элементов после предыдущий компоновки.
// так как никакой компоновки до этого не было.
UIPanel panel2 = new();
stackPanel.Append(panel2);


// флаг `_layoutPreparation == false`.
// все другие ограничители компоновки игнорируются при этой перекомпоновке.
// происходит пересчет размеров и перекомпоновка stakcPanel и всех потомков.
UIExLayout.EndLayoutPreparation(stackPanel); 
```

----

Еще одна проблема: растягивание контейнера или его дочерних элементов. В этом случае размеры будут меняться все время, и, как следствие, каждый кадр будет происходить перекомпоновка.<br><br>
Решения у данной проблемы два:<br>
1. Использовать инструменты `BeginLayoutPreparation` и `EndLayoutPreparation` о которых мы говорили выше. Если вы знаете, что сейчас элемент будет часто изменять размеры, вы можете временно отключить компоновку.
2. Использовать `GlobalRecalculateLayoutDelayMs`, `RecalculateLayoutDelayMs` или `SetRecalculateLayoutDelayMs`:<br>
```csharp
public static int? GlobalRecalculateLayoutDelayMs { get; set; } = null;
public int RecalculateLayoutDelayMs { get; set; } = 0;
public static void SetRecalculateLayoutDelayMsBranch(UIExLayout element, int ms);
```

Данные настройки определены в классе `UIExLayout`. Они отвечают за минимальную задержку в миллисекундах при компоновки определенного элемента.<br>
Т.е. после того, как компоновщик пересчитал компоновку, он устанавливает задержку перед следующей компоновкой в размере `N` ms.<br>
- Если `GlobalRecalculateLayoutDelayMs is not null` - задержку будет определять это свойство.
- Если `GlobalRecalculateLayoutDelayMs is null` - задержку будет определять `RecalculateLayoutDelayMs`.
- Метод `SetRecalculateLayoutDelayMsBranch` позволяет установить задержку переданному элементы и всем потомкам.
